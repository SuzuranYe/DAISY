# DAISY

**Database for Archive Integrity by Suzuran Ye**

当前开发版本：**v1.6.8 界面与核验优化版**｜作者：**Suzuran Ye**｜平台：**Windows**

DAISY 是一套业务任务纯本地、源数据只读的档案登记与核验工具。它可以把目录制作成可审计的
SQLite 快照，比较快照、复核当前文件，并把数据库导出为阅读报告或结构化数据；也可以只读
登记硬盘的 Windows 存储信息与 smartctl 原始证据。

重要：`v1.6.0`、`v1.6.2`、`v1.6.3`、`v1.6.4`、`v1.6.5`、`v1.6.6` 的 GUI 完整扫描
SHA-256 采集功能确认实际失效；这些版本与 `v1.5.1` 的默认功能自检还存在桌面卡顿或卡死风险。
`v1.6.1` 未正式发布。受影响用户应至少升级到 `v1.6.7`；当前开发版本为 `v1.6.8`，
精确边界见[版本演进](Spec/Spec_DAISY_Version_Evolution.md)。

README 只说明现行能力和使用方式。版本变化见
[版本演进](Spec/Spec_DAISY_Version_Evolution.md)，完整约束见
[技术规格](Spec/Spec_DAISY_Technical.md)。

## 功能入口

GUI 只显示 6 个用户入口。兼容 CLI 命令仍保留，但脚本文件不再使用旧域缩写和功能编号。

| 功能入口 | 用途 | 主要产物 |
|---|---|---|
| 档案扫描建库 | 扫描档案目录，建立封存快照；任务支持暂停和续传 | 数据库结构版本 4 的 SQLite 快照；必要时生成 Markdown 问题报告 |
| 档案快照对比 | 比较两份封存快照，记录文件增删、变化、移动与复制 | SQLite Diff 数据库；必要时生成 Markdown 问题报告 |
| 档案数据核验 | 按封存快照复核文件状态与哈希，或在无数据库时直接检查格式、容器与 RAW 解码 | 分板块 Markdown 和 JSON 报告 |
| 档案数据解析 | 只读解析封存快照或 Diff 数据库，按所选数据模块和格式导出 | 自包含 HTML、中文 XLSX、CSV、JSONL、运行清单 |
| 硬盘信息登记 | 只读采集硬盘、分区、卷与 SMART 信息 | 每盘独立 PROFILE ZIP；GUI 默认生成简化报告 TXT |
| 运行环境检测 | 检测 Python、外部工具和可选运行能力 | 可选环境报告 JSON |

`DAISY 功能自检` 位于顶部「高级」菜单，是项目测试入口，不是业务模块。硬盘页的
「检测硬盘」是选择设备前的准备步骤，不另列为功能入口。

## 扫描、暂停与续传

「档案扫描建库」先选择模式，再显示适用设置：

- 完整扫描默认为每个文件计算 SHA-256，提取规范化元数据并保留工具原始输出；扫描页只负责建库，
  不提供格式校验或 RAW 深度校验。
- 完整扫描分别为 ExifTool 与 ffprobe 提供「全量／基础／关闭」：全量另存该工具原始输出，
  基础只保留规范化字段。关闭的工具不处理其适用文件；没有其他适用解析器时显示为「跳过」，
  不列为文件问题。
- 快速扫描只登记目录树和文件属性，不计算哈希，也不提取媒体元数据；参与 Diff 时缺少哈希的
  结论会明确降级为 `hash_missing`，不会仅因文件属性相同而判定内容相同。
- 统一扫描新建快照的文件名只用 `Full`/`Quick` 区分扫描模式；哈希、元数据、NTFS-ID 等
  实际选项以数据库配置和运行清单 (`manifest`) 为准，不再编码进文件名。旧 schema 3 文件名
  仍照常读取。

运行中的扫描可以：

- 点击暂停后先等待当前阶段到达安全边界；此时「继续」和「保存并退出」可见但暂不可用，
  后端确认暂停后才可继续或保存。暂停只适用于当前进程，不等于跨重启续传；
- 保存并退出：安全保存已完成进度；下次启动只显示续传提示，确认后填入续传设置，
  再由用户开始任务；
- 停止任务并保留未完成快照，但下次不主动显示续传提示；用户仍可手动选择。

跨重启不保存 Python 哈希对象或外部工具进程状态。已提交的文件级结果保留；中断时正在
处理的单个文件从起点重试。哈希无进展阈值默认为 90 秒，每增加 9 GiB 再增加 90 秒；
到达阈值时提供「继续等待」「跳过并记录」「停止并保留续传」，无人选择时默认继续等待，
自动处置可在顶部「高级」菜单修改。

设置、进度和日志正文初始均收起。任务开始后收起设置并展开进度和日志；任务真正结束 2 秒后
只收起进度，日志保持展开并接管进度正文释放的高度，不自动展开设置。用户在倒计时内手动切换
进度时以用户操作为准。硬盘检测和依赖安装后的自动环境复检遵守同一规则。

外部工具被视为不可信子进程。ExifTool 会话失效后会回收、重建并有限重试当前文件；
ffprobe、7-Zip、rawpy、哈希工作进程、PowerShell 哈希和 smartctl 均在受控子进程边界内
运行，并记录超时、崩溃和回收结果；会连续处理文件的工具另有有限重试与熔断。工具故障
不会被扩散为大量重复的「文件损坏」记录；数据库结构版本 4 扫描会
转为 `failed_recoverable` 并保留未处理范围，修复工具后可继续。

## 对比、核验与档案数据解析

「档案快照对比」支持数据库结构版本 3→3、3→4、4→3 和 4→4。输入方向决定 `added` 与 `deleted` 语义；
旧库缺少新证据时显示能力不足，不得显示为相同或 0。快照使用中性的「浏览」按钮；页面默认
显示全部基础设置并选择「单目录」，只有改为「多目录」才展开两行式根目录名配对及其内容池。
更换任一快照会恢复「单目录」并清除旧配对，避免把上一组快照的关系误用于新输入。

「档案数据核验」可独立组合：

- 哈希复核：重新计算 SHA-256，并与封存快照中的有效哈希基准逐项比较；
- 基本校验：使用 DAISY 内置校验器检查 ZIP/OOXML 成员 CRC 与 PDF 基础结构；
- ExifTool：适用图片、RAW 和媒体文件的 `-validate`；
- ffprobe：GIF、视频和音频的容器／流结构；
- 7-Zip：压缩包和旧 Office OLE 容器；
- rawpy/LibRaw：在独立子进程中执行 RAW 深度解码。

核验页初始不预选任何方式，并隐藏下方全部内容；先选择「已有数据库」或「无数据库」。已有
数据库时只先展开「路径未变／路径变化」，第二层选完后才显示其余核验内容：
盘符和路径未变可直接使用快照记录的根路径，不需要重复添加档案根目录；路径变化时才显示
根目录映射池，并按根目录名添加当前路径。无数据库时显示独立的档案根目录池，直接遍历当前
文件并执行已选择的格式、容器与 RAW 检查；由于没有基准摘要，哈希复核会禁用，报告不会宣称
内容哈希一致。核验项目使用六个明确按钮，数据库模式下包含独立的「哈希复核」按钮。
核验只接受一份数据库，是因为一次核验使用一套基准；但一份合并快照本身可登记最多 9 个根
目录，所以路径变化时仍可能需要最多 9 项根目录映射，这两项限制并不冲突。

当前会话尚未完成运行环境检测时，页面显示「需要先运行环境检测」，ExifTool、ffprobe、
7-Zip 和 rawpy/LibRaw 均为灰色且不能开始核验。该提示使用与硬盘登记管理员状态相同层级的
琥珀色提示卡，而不是普通说明文字；基本校验是内置能力，不依赖外部工具。
环境检测完成后，只启用已确认可用且由用户选择的项目；新配置除 rawpy/LibRaw 外默认请求
全部项目，暂时灰显
不会覆盖已保存的选择。各工具检查全部适用文件，不提供范围滑块；不支持或无法识别的
格式只计总数，不列为文件问题。当前文件基础状态核对不依赖这些按钮。核验可暂停、继续或
停止，但核验任务不生成未完成快照，因此不提供跨重启续传。工具不可用时对应按钮
禁用并显示原因；RAW 解码失败、文件截断或超时才进入问题报告。ExifTool 与 ffprobe 都适用于
同一文件时按顺序执行并合并结论；前一工具未正常完成时，后一工具不保证继续执行。连续
同类工具故障会停止格式校验阶段，报告同时说明已处理和未处理范围。

「档案数据解析」会先选择数据库，再通过独立的「解析数据库」按钮只读识别快照或 Diff；
选择文件或输入框失去焦点都不会自动读取数据库。解析后显示数据库生成程序版本和可选择的数据模块。快照最多提供
15 个数据模块，Diff 最多提供 6 个数据模块；「导出范围」使用
「全量」「摘要」「自定义」三个按钮。识别成功后一次显示全部导出选项，默认选择「全量」、
全部可选择的数据模块及 HTML/XLSX/CSV/JSONL 四种格式；自定义必须至少选择一个模块才可开始。
模块状态明确区分「0 条记录」和
「无可用记录」。快照模块在界面中使用
「快照概览、问题与诊断、文件清单、目录清单、文件哈希、照片元数据、视频元数据、视频定位点、
音视频轨道、工作图像信息、文档元数据、压缩包与成员、工具原始输出、元数据诊断、扫描运行记录」
15 个短名称；稳定模块 ID 和导出标题不变。模块按钮保持固定尺寸，窗口宽度变化时只重新换行，
并在固定按钮列与独立间距列中对齐；「全选／取消选择」与「浏览」使用相同的小按钮尺寸：

- `Report.html`：无网络依赖的自包含 HTML 阅读首页；
- `Report_Excel.xlsx`：中文工作表、冻结表头、筛选、列宽和大表拆分；
- CSV：稳定字段的机器分析格式，UTF-8 无 BOM、LF；
- JSONL：保留嵌套类型和完整技术值；
- 运行清单 (`manifest`)：记录输入身份、所选数据模块与格式、字段、行数及所有产物摘要。

导出结果先写入唯一暂存目录，完整复核输入和产物后以不覆盖方式发布。Excel 用户应优先打开
XLSX；CSV 保持稳定字段，供脚本和进一步分析，不承担「直接双击即可获得最佳中文排版」的
阅读职责。

## 问题报告

快照 `_Issues.md` 使用固定板块：目录枚举问题、哈希问题、元数据问题、格式校验问题、
RAW 深度校验问题、读取性能异常候选和运行与证据问题。规则如下：

- 已执行且无问题显示 `0`；未执行、旧库未记录或不可解释显示 `NULL`；
- `unsupported`（不支持）、`unknown`（无法判定）和未识别格式只统计总数，不显示路径，
  也不单独触发报告；
- 普通警告、次要警告和字段规范化提示不逐项展开；明确损坏列为问题，高密度异常只列为候选；
- 工具熔断只显示一条聚合事件、影响数量和有限范围，不复制成逐文件问题；
- 读取性能异常只是待复核候选，不能据此断言物理坏区或设备故障。

详细技术证据仍保留在只读 SQLite 或伴随 JSON 中，Markdown 问题报告不承担完整数据库转储。

## 硬盘信息登记

1. 打开「硬盘信息登记」，点击页面内的「管理员模式」按钮，按提示通过 Windows UAC
   重新启动。
2. 返回「硬盘信息登记」，点击「检测硬盘」。
3. 检测期间显示进度与日志；成功后弹窗并刷新硬盘选择，不自动切换设置、进度或日志。
4. 手动展开设置，选择一个或多个联机设备并开始；设置收起，进度与日志展开。

硬盘信息登记只使用 Windows 查询接口和固定 smartctl 只读命令，不启动 SMART 自检，不修改 SMART
设置、磁盘、分区、卷、文件系统或 BitLocker。每个 ZIP 固定包含三类 JSON：

- `*_Manifest.json`：归档身份、采集溯源、命令、状态、采集提示和成员声明；
- `*_Smartctl.json`：`smartctl -x` 原始 JSON 证据；
- `*_Storage.json`：Windows 物理盘、分区、卷、挂载点、BitLocker 和可靠性数据。

最终 ZIP 自动验证文件名指纹、安全路径、成员集合、Manifest、时间、字节数和 CRC。

## 快速开始

### 获取源码

```powershell
git clone https://github.com/SuzuranYe/DAISY.git
Set-Location .\DAISY
```

### 图形界面

双击：

```text
Start_DAISY_GUI.pyw
```

或在 PowerShell 中运行：

```powershell
python .\Script\Script_DAISY_CLI.py gui
```

默认窗口目标为 `1920×1080`，会在较小工作区内收缩；「设置→窗口大小」把
`1920×1080` 放在首项，其后为 `1366×768`、`1600×900`。标准字号和默认窗口设置下，六个页面的初始状态
按当前工作区显示；核验条件项、环境按钮或完整扫描设置真实溢出时才显示并响应滚动条，
最后一项始终可达。
任务开始后自动收起设置、展开进度和日志，并让日志填满剩余高度；运行结束 2 秒后只收起
进度，日志接管释放的高度，设置不自动展开并保留用户手动状态。功能栏在完整界面中固定显示；
「视图」以勾选表示设置区、进度区和日志区当前可见，并可进入或退出小窗模式；日志也可打开为
实时同步的独立窗口。运行进度
和运行日志使用同一组板岩标题栏、暖白标题文字与暖白内容面；三条进度统一使用科研蓝，
进度槽使用石灰。队列、任务阶段和本阶段均保留右侧读数位置；可计算时显示
整数百分比，暂不可计算时明确显示「计算中」。

v1.6.8 的界面配色以《明日方舟_孤星_配色取样_修复版_v2.pptx》为权威来源：档案黑
`#131210`、信号橙 `#F06733`、浅黄字 `#DFD9A9`、先驱青绿 `#88C1B0`、工程黄
`#ECAA3C`、档案深红 `#9A2D28`；深背景 `#11110F`、深色正文 `#171614`、浅色正文／
表面 `#FFF9EF` 和描边 `#6A6257` 作为辅助色。停止动作使用信号橙，警告和续传提示使用
工程黄。明确的「关闭／不采集／不输出」统一使用灰褐底与墨青字，不再按功能分配不同颜色。
大面积底色采用补充色中的暖白 `#F0E7E2`，不再铺满浅黄绿色；补充色也用于进度、日志和
中性状态。批准色板同时约束主窗口与档案数据解析生成的 HTML 报告，生产代码不得出现表外
旧色值。核心配色与可选配色的全部精确数值及用途见
[技术规格 12.3 节](Spec/Spec_DAISY_Technical.md#123-面板与运行状态)；GUI 不使用表外旧色或近似色。

顶部 6 个功能入口保持同一排，分别使用与设置标题一致的六字完整名称；不再显示重复的
「功能模块」文字。按钮固定比例、整组靠左，最左按钮到模块区左、上、下三边的距离与按钮间距
相同。常态与暂停按钮同为天青，当前模块用板岩突出；功能模块外框与所有按钮描边均取消，
状态只通过填充色和文字表现。功能模块整体使用灰褐底色，三色细带位于功能模块与下方内容之间，
只承担分界作用；设置区分割线上方统一使用鼠尾草底和暖白文字，下方内容使用浅色表面。
顶部入口与页面右下角任务按钮采用同一套较大的常驻控件尺寸。「档案扫描建库」默认完整显示，
并选择「完整扫描／全新生成／分别生成」，元数据、文件标识和哈希采集默认全选。二元选项固定
使用统一尺寸按钮；有效选中态为鼠尾草底
和暖白字，明确关闭态统一为灰褐底和墨青字，尚未选中的普通候选项为暖白底和墨青字。
元数据关闭、文件标识不采集、哈希不采集、核验项目关闭和解析格式不输出必须使用同一关闭态
设计。页面模式、导出范围和续传重试范围均使用互斥按钮。
任务表单不创建下拉框；标准菜单栏仍保留 Windows 菜单行为。
普通按钮文字与正文使用相同的 10 号标准字号和常规字重；页内工作流按钮统一使用与
「完整扫描」完全相同的标准尺寸，重要程度只通过角色配色表达，不再额外放大。输入数据库
「选择」使用天青，读取数据库的「解析数据库」使用科研蓝；二者尺寸、字体和内边距一致。
需要改变字段布局的选择采用完整表单离屏构建后一次替换；旧控件不先绘制中间选择态，避免
核验方式切换时先跳一次再重建。不改变字段布局的按钮只原位更新当前值。

扫描页把元数据、文件标识和哈希归入「采集内容」；文件标识按钮在「不采集／NTFS-ID」之间
切换，哈希按钮在「不采集／SHA-256」之间切换。NTFS-ID 由 NTFS 卷序列号与文件索引组成，
用于辅助判断移动和重命名。对比页默认单目录并完整显示基础设置；选择多目录后才显示
根目录名配对；每组的基准与对比
根目录名分为上下两行，不再要求手写 `基准根目录名=对比根目录名`。指纹降级移至
「高级→对比行为」，默认值和 `--force` 语义不变。

顶部菜单固定为「文件／功能／视图／设置／高级／帮助」；「功能」按档案、设备和环境分组，
工具路径归入「设置」，扫描／核验／对比运行选项归入「高级」。菜单文字与正文使用同一
基准字号。顶部「设置」可持久化调整窗口大小、字体、字号、完成提示音和结果目录弹窗；恢复
入口统一为功能栏中的「重置软件」。
标准正文基准为
10 号，并可切换较大或特大字号。提示音默认关闭；
正常完成或「任务完成，但结果需要检查」时异步播放一次，
失败、暂停、保存并退出、停止、依赖安装和硬盘检测准备阶段不播放。任务运行期间关闭窗口
始终要求确认；空闲关闭直接保存配置并退出，不再提供额外确认开关。

页面底部的三个常驻任务按钮与顶部六个功能入口统一尺寸、均不使用描边；日志栏工具按钮采用
统一的小型面板工具规格，其展开按钮到上、下、右三边及左侧相邻按钮的距离相同；
从右向左固定为「开始／停止 → 暂停／继续 → 产出」。同一个科研蓝「开始」按钮在运行时
原位变为橙色「停止」；常态开始使用科研蓝，暂停使用天青，产出使用卡其，左下状态使用
板岩。点击暂停后才在左侧显示「保存并退出」。任务产出有效结果后，
卡其常态配色的「产出」以绿色闪烁两次且不抢焦点；默认
不弹出询问窗口。「设置→结果目录弹窗」开启后，任务结束时才会额外询问是否打开。顶部
功能栏提供「重置软件」，运行期间禁用；该操作恢复窗口、字体和提示设置，并清空任务选项、
会话数据与可重建缓存，但不删除源档案或任务产物。扫描建库、数据核验、快照对比和数据解析
中的目录输入「添加」、根目录配对「添加」与硬盘「检测硬盘」使用科研蓝高对比按钮；数据库
「选择」使用天青，「解析数据库」使用科研蓝。所有这些页内工作流按钮与「完整扫描」采用
完全相同的标准尺寸，只用颜色区分角色。操作按钮位于池子边框外，添加后的目录、配对或硬盘逐行列在下方
`1 px` 灰褐描边池内。纯操作说明行不再额外套框；输出目录和快照对比的快照输入均使用中性的
「浏览」。硬盘页不提供「全选／取消选择」，在独立的「检测硬盘」下方逐盘勾选。管理员权限
未启用时显示浅黄状态区和暗橙主按钮，启用后切换为青绿色状态区。检测完成前不显示硬盘池；
检测完成后先显示硬盘选择，至少选择一块硬盘后才显示输出设置。

功能栏右上角只保留「重置软件」；设置、进度和日志的展开／收起按钮保持固定右侧位置，四组
右侧操作区对齐到同一右边界，设置、进度和日志使用四边等距外边距。点击后不保留焦点虚线框，
展开状态变化不会造成按钮沿 x 轴移动。

档案数据解析按依赖链逐步显示：未选择数据库时只显示数据库「选择」；选定路径但尚未识别时
只增加「解析数据库」；「选择」独占第一行，完整数据库路径显示在第二行，避免长路径挤压操作。
识别成功后一次显示导出范围、数据模块、输出格式和导出目录，默认「全量」并选择全部可选择
模块和四种格式。选择自定义但未选模块、取消全部格式或其他必需输入未完成时，底部「开始」
保持灰色禁用。

六个功能页的首批内容统一显示章节标题，依次使用「扫描设置／对比输入／核验输入／解析输入／
登记准备／检测状态」；单字段首区也不省略标题，条件展开前后不会临时插入标题而造成首项跳动。

扫描页的续传提示位于设置标题下方的独立卡片，不再占用设置标题右侧的操作列；用户确认后
才把受控未完成快照填入续传设置。

DAISY 恢复最后使用的功能页面、白名单内非路径选项和已确认的手动工具路径；不保存普通
档案根目录、输入数据库、输出目录或硬盘选择。选择「保存并退出」时，配置会额外保存
受控的未完成快照路径，用于下次显示续传提示，但不会自动继续扫描。界面设置写入
`Output/GUI_Settings.json`；损坏或非法字段按项回退到安全默认值，`Output` 不进入 Git。

## 运行环境

DAISY 仅支持 Windows，v1.6.8 使用 Python 3.14 验证。

| 依赖 | 使用范围 |
|---|---|
| Python 3.14 | GUI、CLI 与全部模块 |
| ExifTool 13+ | 完整扫描、格式校验、环境检测 |
| ffprobe 8+ | 媒体元数据与格式校验 |
| 7-Zip 24+ | 压缩包／旧文档格式校验 |
| Windows PowerShell 5.1 或 PowerShell 7.x | 哈希复检与 Windows 查询 |
| smartctl 7.5+ | 环境检测与硬盘登记 |
| rawpy/LibRaw（可选） | RAW 深度校验；不可用时功能禁用，不影响档案扫描建库 |

没有 Python 时，可由用户主动运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Script\Script_DAISY_Install_Python.ps1
```

该引导脚本为兼容 Windows PowerShell 5.1 保持 ASCII 英文提示；PowerShell 5.1 可能把
UTF-8 无 BOM 脚本中的非 ASCII 文字按本地代码页误读。脚本只安装或更新 Python 3.14，
Python 与其余工具也可由「运行环境检测」检测，并只在用户确认后安装或更新受支持的项目。

「运行环境检测」使用 7 个可换行排列的双行状态按钮显示 Python、ExifTool、ffprobe、
7-Zip、PowerShell、smartctl 和 rawpy/LibRaw，再用对齐的位置提供安装操作。按钮与
「完整扫描」等模式按钮等宽，高度约为其 1.5 倍；检测成功时第二行直接显示实际版本号，
不再显示笼统的「可用」。可安装项第一行显示
工具名称、第二行显示「安装或更新」，PowerShell 第一行显示名称、第二行显示不可点击的
「手动管理」；DAISY 不负责安装或更新 PowerShell。每次实际安装都需要再次确认；外部工具只通过
固定 WinGet 白名单处理，其中 Python 固定使用 Python 3.14 包；rawpy 只通过当前 Python 环境的
固定 pip 白名单处理。手动工具路径统一位于
「设置→工具路径」。点击安装按钮后先在后台查询软件源最新版本，但不执行安装；查询成功后才显示
当前检测版本与软件源最新版本并询问是否安装或更新，查询失败或无法识别版本时不执行安装。
安装结束后自动复检，并在日志与状态栏列出当前版本（安装前）、软件源最新版本和更新后版本；未识别或
安装失败时不会显示为更新成功。PowerShell 状态卡和本机版本摘要只显示主次版本。缺失工具
或可选能力时仍显示「环境检测完成」，并明确列出缺失项，不把缺失误写成任务失败。环境报告
默认不导出；开启「检测报告」后才显示目录并生成 JSON 文件。

## 输出目录

| 目录 | 内容 | 是否可重建 |
|---|---|---|
| `Output/Snapshots` | 数据库结构版本 3/4 封存快照和运行中的未完成快照 | 封存快照应长期保留 |
| `Output/Diffs` | 两份快照的变更数据库 | 可由原快照重建 |
| `Output/Reports` | 环境与核验报告、档案数据解析结果 | 可由输入数据与当前环境重建 |
| `Output/Storage` | 每块硬盘的 PROFILE ZIP 与 GUI 默认生成的简化报告 TXT | 需重新读取对应硬盘 |

导出结果和硬盘档案 ZIP 可能包含路径、卷标、序列号、卷 GUID、计算机名、PNP Device ID 或
BitLocker 状态；公开分享前必须人工检查。

## 安全与兼容边界

- 源档案只读；扫描、核验、Diff 和解析不会写回源文件。
- 封存数据库只读；分析产生新文件，不原地迁移或补列。
- 业务运行纯本地；只有用户确认的 WinGet 或 rawpy pip 安装流程可能访问软件源。
- 最终 SQLite、Diff、导出目录和硬盘档案 ZIP 均以不覆盖方式发布。
- v1.6.0 起统一扫描生成 schema 4；旧 `full-scan`、`quick-scan` 兼容入口继续生成冻结的
  schema 3。新程序所有封存数据库消费者至少只读支持 v1.4.1/schema 3。
- 旧库缺少 schema 4 能力时显示 `NULL（未记录）`，不得显示为 0、空或成功；旧库前后摘要、
  大小和 mtime 必须不变。
- 兼容保证是「v1.6.8 读取 v1.4.1 封存库」，不保证 v1.4.1 程序读取 schema 4，也不允许
  v1.6.8 直接接管 v1.4.1 未完成的工作快照。
- 多个 GUI 窗口彼此拥有独立表单、日志、控制流和子进程句柄，但仍共享磁盘 I/O、外部工具
  和用户指定输出目录；并发任务应使用不同的输出目录，或确保目标名称不会冲突。

详细契约见[技术规格](Spec/Spec_DAISY_Technical.md)。
