# DAISY

**Database for Archive Integrity by Suzuran Ye**

当前版本：**v1.6.6 长期稳定版**｜作者：**Suzuran Ye**｜平台：**Windows**

DAISY 是一套业务任务纯本地、源数据只读的档案登记与核验工具。它可以把目录制作成可审计的
SQLite 快照，比较快照、复核当前文件，并把数据库导出为阅读报告或结构化数据；也可以只读
登记硬盘的 Windows 存储信息与 smartctl 原始证据。

README 只说明现行能力和使用方式。版本变化见
[版本演进](Spec/Spec_DAISY_Version_Evolution.md)，完整约束见
[技术规格](Spec/Spec_DAISY_Technical.md)。

## 功能入口

GUI 只显示 6 个用户入口。内部 DBS 编号和旧 CLI 仍保留，避免破坏既有脚本。

| 功能入口 | 用途 | 主要产物 |
|---|---|---|
| 档案扫描建库 | 扫描档案目录，生成可暂停、可续传的快照 | 数据库结构版本 4 的 SQLite 快照；必要时生成 Markdown 问题报告 |
| 档案快照对比 | 比较两份快照，记录文件增删、变化、移动与复制 | SQLite Diff 数据库；必要时生成 Markdown 问题报告 |
| 档案数据核验 | 按快照核对现有文件，检查格式、容器与 RAW 解码 | 分板块 Markdown 和 JSON 报告 |
| 档案数据解析 | 解析快照或 Diff，按所选数据模块和格式导出 | 自包含 HTML、中文 XLSX、CSV、JSONL、运行清单 |
| 硬盘信息登记 | 采集硬盘、分区、卷与 SMART 信息 | 每盘独立 PROFILE ZIP；GUI 默认生成简化报告 TXT |
| 运行环境检测 | 检测各功能所需工具和可选能力 | 环境报告 JSON |

`DBS-91 DAISY 功能自检` 位于顶部「高级」菜单，是项目测试入口，不是业务模块。硬盘页的
「检测硬盘」是选择设备前的准备步骤，不另占功能编号。

## 扫描、暂停与续传

「档案扫描建库」先选择模式，再显示适用设置：

- 完整扫描默认为每个文件计算 SHA-256，提取规范化元数据并保留工具原始输出；扫描页只负责建库，
  不提供格式校验或 RAW 深度校验。
- 完整扫描分别为 ExifTool 与 ffprobe 提供「全量／基础／关闭」：全量另存该工具原始输出，
  基础只保留规范化字段。关闭的工具不处理其适用文件；没有其他适用解析器时显示为「跳过」，
  不列为文件问题。
- 快速扫描只登记目录树和文件属性，不计算哈希，也不提取媒体元数据；参与 Diff 时缺少哈希的
  结论会明确降级为 `hash_missing`，不会仅因文件属性相同而判定内容相同。
- 统一扫描新建快照的文件名只用 `Full`/`Quick` 区分扫描模式；哈希、元数据、NTFS-ID 等
  实际选项以数据库配置和运行清单 (`manifest`) 为准，不再编码进文件名。旧 schema 3 文件名
  仍照常读取。

运行中的扫描可以：

- 点击暂停后先等待当前阶段到达安全边界；此时「继续」和「保存并退出」可见但暂不可用，
  后端确认暂停后才可继续或保存。暂停只适用于当前进程，不等于跨重启续传；
- 保存并退出：安全保存已完成进度；下次启动只显示续传提示，确认后填入续传设置，
  再由用户开始任务；
- 停止任务并保留未完成快照，但下次不主动显示续传提示；用户仍可手动选择。

跨重启不保存 Python 哈希对象或外部工具进程状态。已提交的文件级结果保留；中断时正在
处理的单个文件从起点重试。哈希无进展阈值默认为 90 秒，每增加 9 GiB 再增加 90 秒；
到达阈值时提供「继续等待」「跳过并记录」「停止并保留续传」，无人选择时默认继续等待，
自动处置可在顶部「高级」菜单修改。

任务队列真正结束后，GUI 会重新展开设置，方便调整后再次运行；若结束时处于小窗模式，
会先返回完整界面。依赖安装后的自动环境复检完成后再展开设置，硬盘检测则返回专用的
硬盘选择布局。

外部工具被视为不可信子进程。ExifTool 会话失效后会回收、重建并有限重试当前文件；
ffprobe、7-Zip、rawpy、哈希工作进程、PowerShell 哈希和 smartctl 均在受控子进程边界内
运行，并记录超时、崩溃和回收结果；会连续处理文件的工具另有有限重试与熔断。工具故障
不会被扩散为大量重复的「文件损坏」记录；数据库结构版本 4 扫描会
转为 `failed_recoverable` 并保留未处理范围，修复工具后可继续。

## 对比、核验与档案数据解析

「档案快照对比」支持数据库结构版本 3→3、3→4、4→3 和 4→4。输入方向决定 `added` 与 `deleted` 语义；
旧库缺少新证据时显示能力不足，不得显示为相同或 0。

「档案数据核验」可独立组合：

- 基本校验：使用 DAISY 内置校验器检查 ZIP/OOXML 成员 CRC 与 PDF 基础结构；
- ExifTool：适用图片、RAW 和媒体文件的 `-validate`；
- ffprobe：GIF、视频和音频的容器／流结构；
- 7-Zip：压缩包和旧 Office OLE 容器；
- rawpy/LibRaw：在独立子进程中执行 RAW 深度解码。

当前会话尚未完成运行环境检测时，页面显示「需要先运行环境检测」，ExifTool、ffprobe、
7-Zip 和 rawpy/LibRaw 均为灰色且不能开始核验。该提示使用与硬盘登记管理员状态相同层级的
琥珀色提示卡，而不是普通说明文字；基本校验是内置能力，不依赖外部工具。
环境检测完成后，只启用已确认可用且由用户选择的项目；新配置默认请求全部项目，暂时灰显
不会覆盖已保存的选择。各工具检查全部适用文件，不提供范围滑块；不支持或无法识别的
格式只计总数，不列为文件问题。当前文件基础状态核对不依赖这些按钮。核验可暂停、继续或
停止，但核验任务不生成未完成快照，因此不提供跨重启续传。工具不可用时对应按钮
禁用并显示原因；RAW 解码失败、文件截断或超时才进入问题报告。ExifTool 与 ffprobe 都适用于
同一文件时按顺序执行并合并结论；前一工具未正常完成时，后一工具不保证继续执行。连续
同类工具故障会停止格式校验阶段，报告同时说明已处理和未处理范围。

「档案数据解析」会先选择数据库，再通过独立的「解析数据库」按钮只读识别快照或 Diff；
选择文件或输入框失去焦点都不会自动读取数据库。解析后显示来源版本和可用数据模块。快照最多提供
15 个数据模块，Diff 最多提供 6 个数据模块；「导出范围」使用
「摘要」「全部」「自定义」三个按钮，默认选择「全部」。「数据模块」随导出范围
同步刷新；模块状态明确区分「0 条记录」和「无可用记录」。快照模块在界面中使用
「快照概览、问题与诊断、文件清单、目录清单、文件哈希、照片元数据、视频元数据、视频定位点、
音视频轨道、工作图像信息、文档元数据、压缩包与成员、工具原始输出、元数据诊断、扫描运行记录」
15 个短名称；稳定模块 ID 和导出标题不变。模块按钮保持固定尺寸，窗口宽度变化时只重新换行，
并在容器四边使用相同留白；「全选／取消选择」与「浏览」使用相同的小按钮尺寸。四种输出格式默认全部选择，
也可独立关闭：

- `Report.html`：无网络依赖的自包含 HTML 阅读首页；
- `Report_Excel.xlsx`：中文工作表、冻结表头、筛选、列宽和大表拆分；
- CSV：稳定字段的机器分析格式，UTF-8 无 BOM、LF；
- JSONL：保留嵌套类型和完整技术值；
- 运行清单 (`manifest`)：记录输入身份、所选数据模块与格式、字段、行数及所有产物摘要。

导出结果先写入唯一暂存目录，完整复核输入和产物后以不覆盖方式发布。Excel 用户应优先打开
XLSX；CSV 保持稳定字段，供脚本和进一步分析，不承担「直接双击即可获得最佳中文排版」的
阅读职责。

## 问题报告

快照 `_Issues.md` 使用固定板块：目录枚举问题、哈希问题、元数据问题、格式校验问题、
RAW 深度校验问题、读取性能异常候选和运行与证据问题。规则如下：

- 已执行且无问题显示 `0`；未执行、旧库未记录或不可解释显示 `NULL`；
- `unsupported`（不支持）、`unknown`（无法判定）和未识别格式只统计总数，不显示路径，
  也不单独触发报告；
- 普通警告、次要警告和字段规范化提示不逐项展开；明确损坏列为问题，高密度异常只列为候选；
- 工具熔断只显示一条聚合事件、影响数量和有限范围，不复制成逐文件问题；
- 读取性能异常只是待复核候选，不能据此断言物理坏区或设备故障。

详细技术证据仍保留在只读 SQLite 或伴随 JSON 中，Markdown 问题报告不承担完整数据库转储。

## 硬盘信息登记

1. 打开「硬盘信息登记」，点击页面内的「管理员模式」按钮，按提示通过 Windows UAC
   重新启动。
2. 返回「硬盘信息登记」，点击「检测硬盘」。
3. 检测期间显示进度与日志；成功后弹窗并自动返回展开的硬盘选择区。
4. 选择一个或多个联机设备并开始；设置再次收起，进度与日志展开。

STG 只使用 Windows 查询接口和固定 smartctl 只读命令，不启动 SMART 自检，不修改 SMART
设置、磁盘、分区、卷、文件系统或 BitLocker。每个 ZIP 固定包含三类 JSON：

- `*_Manifest.json`：归档身份、采集溯源、命令、状态、采集提示和成员声明；
- `*_Smartctl.json`：`smartctl -x` 原始 JSON 证据；
- `*_Storage.json`：Windows 物理盘、分区、卷、挂载点、BitLocker 和可靠性数据。

最终 ZIP 自动验证文件名指纹、安全路径、成员集合、Manifest、时间、字节数和 CRC。

## 快速开始

### 获取源码

```powershell
git clone https://github.com/SuzuranYe/DAISY.git
Set-Location .\DAISY
```

### 图形界面

双击：

```text
Start_DAISY_GUI.pyw
```

或在 PowerShell 中运行：

```powershell
python .\Script\Script_DAISY_MAIN.py gui
```

默认窗口目标为 `1600×900`，会在较小工作区内收缩；设置中的 3 个预设按分辨率升序排列为
`1366×768`、`1600×900`、`1920×1080`。标准字号和默认窗口设置下，六个页面的初始状态
完整可见；选择完整扫描等条件后若设置真实溢出，才显示并响应滚动条，最后一项始终可达。
任务开始后自动收起设置、
展开进度和日志，并让日志填满
剩余高度。「视图」以勾选表示功能栏、设置区、进度区和日志区当前可见，并可进入或退出
小窗模式；日志也可打开为实时同步的独立窗口。运行进度
和运行日志使用同一组暖米色面板底色，避免进度区域在默认主题下显得过白。

顶部 6 个功能入口保持同一排，标题均为 4 个字；按钮固定比例、整组靠左，以暖米黄色区分
普通与当前页面。进入「档案扫描建库」时不会预选扫描模式；必须先选择「完整扫描」或
「快速扫描」，随后才显示该模式的设置。二元选项固定使用
统一尺寸按钮，开启为绿、关闭为黄；页面模式、导出范围和续传重试范围均使用互斥按钮。
任务表单不创建下拉框；标准菜单栏仍保留 Windows 菜单行为。
所有按钮文字与正文使用相同的 10 号标准字号和常规字重；颜色仍用于表达主操作、选择和状态，
不再通过放大或加粗按钮文字制造层级。
扫描设置切换采用完整表单离屏构建后一次替换；不改变字段布局的按钮只更新当前值，避免
先清空再重建造成的可见闪动。档案数据解析的摘要／全部／自定义预设只原位更新模块选择，
不销毁输入框、输出格式或表单容器。

扫描页把元数据、文件标识和哈希归入「采集内容」；文件标识按钮在「不采集／NTFS-ID」之间
切换，哈希按钮在「不采集／SHA-256」之间切换。NTFS-ID 由 NTFS 卷序列号与文件索引组成，
用于辅助判断移动和重命名。对比页的根目录对应使用左右两栏配对编辑器，不再要求
手写 `基准根目录名=对比根目录名`；指纹降级移至「高级→对比行为」，默认值和 `--force`
语义不变。

顶部菜单固定为「文件／功能／视图／设置／高级／帮助」；「功能」按档案、设备和环境分组，
工具路径归入「设置」，扫描／核验／对比运行选项归入「高级」。菜单文字与正文使用同一
基准字号。顶部「设置」可持久化调整窗口大小、字体、字号、完成提示音和结果目录弹窗；恢复
入口统一为功能栏中的「重置软件」。
标准正文基准为
10 号，并可切换较大或特大字号。提示音默认关闭；
正常完成或「任务完成，但结果需要检查」时异步播放一次，
失败、暂停、保存并退出、停止、依赖安装和硬盘检测准备阶段不播放。任务运行期间关闭窗口
始终要求确认；空闲关闭直接保存配置并退出，不再提供额外确认开关。

页面底部的三个常驻任务按钮与日志栏三个工具按钮等宽，并与「完整扫描」等表单按钮等高；
从右向左固定为「开始／停止 → 暂停／继续 → 产出」。同一个绿色「开始」按钮在运行时
原位变为橙色「停止」，点击暂停后才在左侧显示「保存并退出」。任务产出有效结果后，
与顶部六个功能入口使用同一米黄色常态配色的「产出」以绿色闪烁两次且不抢焦点；默认
不弹出询问窗口。「设置→结果目录弹窗」开启后，任务结束时才会额外询问是否打开。顶部
功能栏提供「重置软件」，运行期间禁用；该操作恢复窗口、字体和提示设置，并清空任务选项、
会话数据与可重建缓存，但不删除源档案或任务产物。文件选择小按钮统一使用
「添加／选择／浏览」，各面板的展开／收起按钮使用相同尺寸。

DAISY 恢复最后使用的功能页面、白名单内非路径选项和已确认的手动工具路径；不保存普通
档案根目录、输入数据库、输出目录或硬盘选择。选择「保存并退出」时，配置会额外保存
受控的未完成快照路径，用于下次显示续传提示，但不会自动继续扫描。界面设置写入
`Output/GUI_Settings.json`；损坏或非法字段按项回退到安全默认值，`Output` 不进入 Git。

### 命令行

```powershell
python .\Script\Script_DAISY_MAIN.py --help
python .\Script\Script_DAISY_MAIN.py scan --mode full --root "Archive=E:\Archive"
python .\Script\Script_DAISY_MAIN.py scan --resume .\Output\Snapshots\任务.partial.sqlite
python .\Script\Script_DAISY_MAIN.py diff --old .\old.sqlite --new .\new.sqlite
python .\Script\Script_DAISY_MAIN.py verify --snapshot .\baseline.sqlite --root "Archive=E:\Archive"
python .\Script\Script_DAISY_MAIN.py parse-db --database .\baseline.sqlite --format html --format xlsx
python .\Script\Script_DAISY_MAIN.py storage-list
python .\Script\Script_DAISY_MAIN.py storage-collect --disk-number 3
```

`full-scan` 和 `quick-scan` 继续作为冻结的 v1.4.1 兼容入口；`check-hash`、`check-format`
和 `export-report` 继续作为旧版兼容入口。新 GUI 使用 `scan`、`verify` 和 `parse-db`。
这些入口仍保留原有英文参数名和取值，现行中文术语不会改写既有命令行协议。

## 运行环境

DAISY 仅支持 Windows，v1.6.6 使用 Python 3.14 验证。

| 依赖 | 使用范围 |
|---|---|
| Python 3.14 | GUI、CLI 与全部模块 |
| ExifTool 13+ | 完整扫描、格式校验、环境检测 |
| ffprobe 8+ | 媒体元数据与格式校验 |
| 7-Zip 24+ | 压缩包／旧文档格式校验 |
| Windows PowerShell 5.1 或 PowerShell 7.x | 哈希复检与 Windows 查询 |
| smartctl 7.5+ | 环境检测与硬盘登记 |
| rawpy/LibRaw（可选） | RAW 深度校验；不可用时功能禁用，不影响档案扫描建库 |

没有 Python 时，可由用户主动运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Script\Script_DAISY_Install_Python.ps1
```

该引导脚本为兼容 Windows PowerShell 5.1 保持 ASCII 英文提示；PowerShell 5.1 可能把
UTF-8 无 BOM 脚本中的非 ASCII 文字按本地代码页误读。脚本只安装或更新 Python 3.14，
其余工具由「运行环境检测」负责检测，并只在用户确认后安装受支持的项目。

「运行环境检测」先用一排 6 个紧凑、固定宽度的完整名称状态按钮显示 ExifTool、ffprobe、
7-Zip、PowerShell、smartctl 和 rawpy/LibRaw，再用完全对齐的 6 个位置提供安装操作；可安装项第一行显示
工具名称、第二行显示「安装或更新」，PowerShell 第一行显示名称、第二行显示不可点击的
「系统提供」。每次实际安装都需要再次确认；外部工具只通过
固定 WinGet 白名单处理，rawpy 只通过当前 Python 环境的固定 pip 白名单处理。手动工具路径统一位于
「设置→工具路径」。点击安装按钮后先在后台查询软件源最新版本，但不执行安装；查询成功后才显示
当前检测版本与软件源最新版本并询问是否安装或更新，查询失败或无法识别版本时不执行安装。
安装结束后自动复检，并在日志与状态栏列出当前版本（安装前）、软件源最新版本和更新后版本；未识别或
安装失败时不会显示为更新成功。

## 输出目录

| 目录 | 内容 | 是否可重建 |
|---|---|---|
| `Output/Snapshots` | 数据库结构版本 3/4 封存快照和运行中的未完成快照 | 封存快照应长期保留 |
| `Output/Diffs` | 两份快照的变更数据库 | 可由原快照重建 |
| `Output/Reports` | 环境与核验报告、档案数据解析结果 | 可由输入数据与当前环境重建 |
| `Output/Storage` | 每块硬盘的 PROFILE ZIP 与 GUI 默认生成的简化报告 TXT | 需重新读取对应硬盘 |

导出结果和硬盘档案 ZIP 可能包含路径、卷标、序列号、卷 GUID、计算机名、PNP Device ID 或
BitLocker 状态；公开分享前必须人工检查。

## 安全与兼容边界

- 源档案只读；扫描、核验、Diff 和解析不会写回源文件。
- 封存数据库只读；分析产生新文件，不原地迁移或补列。
- 业务运行纯本地；只有用户确认的 WinGet 或 rawpy pip 安装流程可能访问软件源。
- 最终 SQLite、Diff、导出目录和硬盘档案 ZIP 均以不覆盖方式发布。
- v1.6.0 起统一扫描生成 schema 4；旧 `full-scan`、`quick-scan` 兼容入口继续生成冻结的
  schema 3。新程序所有封存数据库消费者至少只读支持 v1.4.1/schema 3。
- 旧库缺少 schema 4 能力时显示 `NULL（未记录）`，不得显示为 0、空或成功；旧库前后摘要、
  大小和 mtime 必须不变。
- 兼容保证是「v1.6.6 读取 v1.4.1 封存库」，不保证 v1.4.1 程序读取 schema 4，也不允许
  v1.6.6 直接接管 v1.4.1 未完成的工作快照。
- 多个 GUI 窗口彼此拥有独立表单、日志、控制流和子进程句柄，但仍共享磁盘 I/O、外部工具
  和用户指定输出目录；并发任务应使用不同的输出目录，或确保目标名称不会冲突。

详细契约见[技术规格](Spec/Spec_DAISY_Technical.md)、
[v1.6.0 数据与恢复契约](Spec/Spec_DAISY_V1_6_0_Data_Contract.md)和
[v1.6.0 数据库解析设计](Spec/Spec_DAISY_V1_6_0_Database_Parsing_Design.md)。

## 项目结构

```text
DAISY/
├─ Start_DAISY_GUI.pyw
├─ Script/
│  ├─ Script_DAISY_MAIN.py
│  ├─ Script_DAISY_GUI.py
│  ├─ Module/                 # 统一入口与冻结兼容入口
│  ├─ Lib/                    # Reader、状态机、扫描、核验、解析、STG
```

GUI 负责参数、状态和进程控制；业务逻辑仍由同一 CLI/Module 层执行。
