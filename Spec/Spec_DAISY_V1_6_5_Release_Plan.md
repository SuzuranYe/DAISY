# DAISY v1.6.5 长期生产维护版本发布计划

- 目标版本：v1.6.5
- 发布性质：长期生产维护版本
- 生产谱系：v1.4.1 → v1.6.4 → v1.6.5
- 发布基线：v1.6.4 发布提交 `6b54f57c390aaa8073a4357b71c2cfeccc8e61f9`
- 当前状态：发布门禁通过，待提交与推送
- 数据兼容基线：v1.4.1/schema 3 FULL 封存快照

## 一、版本定位

v1.6.5 是 v1.6.4 长期生产基线的补丁版本，只维护 GUI 可见性、控件对齐、操作说明和
相应测试及文档。现有 `v1.6.4` 标签保持不变；本版使用新的 `v1.6.5` 注释标签，不改写
任何历史引用。

## 二、本版变更

1. 「视图」菜单把功能栏、设置区、进度区和日志区改为固定复选项；面板可见即勾选，
   隐藏即取消。「小窗模式／完整界面」仍是独立模式命令。
2. 硬盘登记页的「管理员模式」与「检测硬盘」使用相同请求尺寸和左边缘；管理员按钮位于
   权限状态文字前，并与文字在同一 Y 轴居中。
3. 硬盘检测操作行直接说明读取硬盘、分区、卷与 SMART 信息并生成可登记清单；硬盘选择
   提示直接说明选择对象及重新检测会清除当前选择。
4. 数据库解析操作行明确区分来源版本与结构版本，并继续保证只有点击「解析数据库」才读取
   输入数据库。
5. 数据核验的环境门控说明改为「完成环境检测后，才可选择并开始核验」。
6. DBS `SCANNER_VERSION` 与 STG `APP_VERSION` 更新为 `1.6.5`。

## 三、冻结数据与兼容边界

- 旧版 DBS `SCHEMA_VERSION=3`、统一扫描 `SCHEMA_VERSION=4`、STG
  `ARCHIVE_SCHEMA_VERSION=3`、元数据 `PROFILE_VERSION=7` 保持不变。
- v1.4.1/schema 3 FULL 封存库继续由统一 Reader 只读打开；不得迁移、补列或回写旧库。
- 冻结兼容入口、扫描与恢复状态机、Diff、哈希、元数据、核验、数据库解析、问题报告和
  STG 归档实现不得因本版 UI 修改而改变。
- 应用版本变化只更新新产物记录的程序版本，不代表数据库或归档结构升级。

## 四、发布门禁

1. 对最终发布树运行完整发现式自动化套件，并使用 `-W error` 把警告视为失败。
2. 运行 Python 编译、PowerShell AST、UTF-8 无 BOM、LF、Markdown 链接、
   `git diff --check` 和禁止双方括号链接检查。
3. 核对 v1.6.4 至当前 `Script/Lib` 和 `Script/Module` 差异，除 DBS、STG 应用版本号外
   不得出现业务实现变化。
4. 复核新增真实 Tk 用例覆盖视图勾选状态、管理员／检测按钮对齐、硬盘说明、数据库解析
   操作及核验门控文案。
5. 把最终测试数量、耗时、静态门禁和限制写入
   [v1.6.5 测试记录](Spec_DAISY_V1_6_5_Test_Record.md)。

任一门禁失败都必须先修复并重新运行相应范围；不得把部分通过描述为完整发布验收通过。

## 五、发布流程

- 用户已明确授权运行全量测试、提交、更新 `main`、推送并创建标签。
- 所有修改先在 `Codex` 分支提交；远端引用复核无分叉后，`main` 只允许快进到同一提交。
- 创建注释标签 `v1.6.5`，标签说明为 `DAISY v1.6.5`；不得移动或覆盖 `v1.6.4`。
- 原子推送 `Codex`、`main` 和 `v1.6.5` 后重新获取远端引用，确认
  `origin/Codex == origin/main == v1.6.5^{}`。
