## 一、目标与边界

v1.6.1 是 v1.6.0 之上的 UI、交互和可选元数据采集优化，不升级 SQLite schema，
不修改 Diff 计算或数据库业务投影，不原地迁移任何旧数据库，也不改变冻结的 `full-scan`、
`quick-scan` 对应的 schema 3 CLI 参数集合。现行 GUI 的「档案扫描建库」只负责建立数据库；格式、容器和 RAW
解码检查归入独立的「档案数据核验」，结果只进入报告，不回写封存数据库。为兼容 v1.6.0
脚本，统一 `scan` CLI 已有的格式与 RAW 参数继续保留原语义，但不作为 v1.6.1 GUI 入口。

本轮只允许统一 `scan` 的 schema 4 配置新增两个逐工具冻结范围键：

- `metadata_exiftool_mode: complete/normalized/off`；
- `metadata_ffprobe_mode: complete/normalized/off`。

既有 `metadata_storage`、`metadata_exiftool` 和 `metadata_ffprobe` 保留为兼容字段。旧
schema 4 未完成快照 (`.partial.sqlite`) 缺少逐工具范围键时，按既有全局范围和布尔开关解释，
以保持 v1.6.0 行为。
新键只决定对应工具是否运行及其既有 `raw_payloads.provider` 是否保留，不新增表、列、索引
或约束。扫描页不再提供格式校验或 RAW 深度校验选项；数据核验使用自己的工具选择，不复用扫描
元数据范围。

## 三、界面结构

### 3.1 顶部功能入口

六个入口使用与表单模式按钮相同的原生 Tk 平直按钮结构、边框和正文字号；顶部尺寸按
普通按钮同比放大，按钮列不参与横向拉伸，整组在可用区域靠左。普通态、悬停态和选中态均
使用层次清晰的暖米黄色系，当前页采用较深米黄色；状态变化不改变字体、`padding`、`border` 或 `width`。

### 3.2 扫描页两阶段交互

扫描页状态分为：

1. `scan_mode=""`：只渲染「扫描模式」行及两个模式按钮；运行校验必须提示选择模式；
2. `scan_mode="full"`：展开任务设置、采集内容和完整扫描从属设置；
3. `scan_mode="quick"`：展开任务设置和快速扫描允许的 `NTFS-ID` 设置，不渲染元数据或哈希
   控件。

完整扫描只保留建库所需的目录、生成方式、元数据、`NTFS-ID`、哈希及输出设置；`NTFS-ID`
明确表示由 NTFS 卷序列号和文件索引组成的辅助身份信息。完整扫描与
快速扫描均不得渲染格式校验或 RAW 深度校验；这两项不能出现在扫描高级菜单或命令预览中。

完整扫描与快速扫描切换时先收集当前可见值，再在 Tk 事件返回后重建条件表单，避免销毁事件源
导致 Tcl/Tk 选择状态丢失。应用重启恢复上次页面和经过白名单过滤的非路径选项，但不持久
保存普通档案目录、输入数据库或输出路径；工具路径使用独立白名单保存。选择「保存并退出」
时，只额外保存受控未完成快照路径，用于下次显示续传提示。

### 3.3 二元按钮与核验项目行

- 二元按钮拥有固定字符宽度和固定 padding；开启为深绿白字，关闭为琥珀色深字；
- 所有严格 `{False, True}` 字段固定使用按钮，不读取或写入控件样式配置；旧配置中的
  `binary_control_style` 作为未知键忽略；
- 元数据合并为一行，只显示 ExifTool 与 ffprobe 两个按钮；每个按钮独立按
  `全量 → 基础 → 关闭 → 全量` 循环，不再为三个状态各占一个按钮，也不保留共享范围按钮；
- 数据核验的「核验项目」固定为一行五个按钮：`内置格式校验`、`ExifTool`、`ffprobe`、
  `7-Zip`、`rawpy/LibRaw`；
- 五个按钮使用相同高度、字符宽度、padding 和间距，状态变化只能改变颜色和文字，不能
  改变外框尺寸；
- 普通按钮组统一使用 12 px 水平间距；顶部六入口和文件选择按钮使用各自专用尺寸；
- 能力可用的五项默认全部开启。关闭时只执行不依赖这些工具的基础文件状态核对；开启后检查该工具
  全部适用文件，不提供抽样滑块；
- RAW 深度校验不可用时按钮禁用，并由悬停提示显示统一能力探测层返回的原因；其他工具只在
  被选择时参加预检。

对比页的 `--map-root` 不再使用无结构多行文本框。GUI 显示「基准根目录名」和
「对比根目录名」两列，并解释其通常来自建库时所选根目录的文件夹名称；通过 `→` 和
「添加配对」构成列表，提交时仍无损序列化为既有
`基准根目录名=对比根目录名` 参数。指纹降级不占页面行，只在「高级→对比行为」中设置。

### 3.4 数据核验板块

数据核验与数据库建立是两个独立功能板块。核验输入接受一个封存数据库及当前根目录映射，
只读取得 `roots`、`entries`、`hashes` 和快照身份；不能要求数据库含有历史校验字段。

各开关语义如下：

| 开关 | 适用内容 | 执行器 |
|---|---|---|
| 内置格式校验 | ZIP/OOXML 成员 CRC、PDF 头尾与交叉引用结构 | 隔离 Python 子进程 |
| ExifTool | 适用图片、RAW、GIF、音视频等的 `-validate` 诊断 | 受控 ExifTool 子进程 |
| ffprobe | GIF、视频和音频的容器／流结构 | 受控 ffprobe 子进程 |
| 7-Zip | 7z/RAR 等压缩包及旧 Office OLE 容器 | 受控 7-Zip 子进程 |
| rawpy/LibRaw | rawpy/LibRaw 支持的 RAW 实际解码 | 一次性隔离 Python 子进程 |

ExifTool 与 ffprobe 必须可以单独运行；只选择 ffprobe 时不能隐式启动 ExifTool，反之亦然。
两者都适用于同一文件且都已选择时，当前执行顺序为 ExifTool 后 ffprobe，并把诊断合并为
一条格式校验结论。前一工具未能正常完成时，后一工具不保证继续执行；连续同类工具故障会
停止整个格式校验阶段，并在报告中记录已处理和未处理范围。未识别、不支持或不适用的文件
类型只进入相应统计，不写入问题列表。

### 3.5 下拉重复选择

现行正式页面仅续传重试范围保留下拉选择；本节同时保护配置迁移所需的兼容表单。
`<<ComboboxSelected>>` 处理器必须优先读取 `Combobox.current()` 对应的稳定内部值。若新旧
内部值相同，立即恢复显示标签、清除编辑框选区，并在当前 Tcl/Tk 事件结束后的 idle 回调中
再校正一次；不得销毁或重建该控件。`TCombobox` 和 `Daisy.TCombobox` 必须显式覆盖普通、
只读、焦点、按下和禁用状态的前景色、选择前景色与选择背景色，不能继承 Windows 主题的
白色 `SystemHighlightText`。只有内部值真的变化时才延迟重建条件表单。

### 3.6 软件安装

- 软件安装区使用单排六列：ExifTool、ffprobe、7-Zip、PowerShell、smartctl、rawpy；
  可安装项第一行显示工具名称，第二行显示「安装或更新」；PowerShell 第一行显示名称、
  第二行显示「系统提供」并禁用；上下两排按钮复用相同宽高、内边距和 12 px 间距；
- 外部工具继续使用固定 WinGet 包 ID；rawpy 使用当前 GUI 所属 Python 执行
  `python -m pip install --upgrade --upgrade-strategy only-if-needed rawpy`；
- 安装命令只接受固定白名单名称，不接受任意包名；测试只模拟命令和确认框，不执行联网
  安装；
- 确认文案必须说明会修改当前 Python 环境和必要依赖。安装结束后重新运行环境检测，由统一能力
  探测层在独立子进程验证 rawpy/LibRaw；Tk 主进程不得导入 rawpy。

### 3.7 环境状态与目录选择

- 环境页按「检测状态 → 软件安装 → 环境报告目录」的顺序排列；
- 检测状态一行显示 ExifTool、ffprobe、7-Zip、PowerShell、smartctl、rawpy 六个等尺寸
  状态按钮；点击任一按钮均重新执行完整环境检测，已有结果时也可再次检测；
- 「等待检测」「可用」「不可用」分别使用灰、绿、红三态，悬停显示完整版本、路径或原因；
- 扫描和核验的「添加目录」均位于路径内容上方并从左侧起排；路径列表或映射框独占下一行；
- 无溢出判定允许 2 px Tk 几何取整容差，避免肉眼未溢出却出现空滚动；真实溢出仍必须
  显示滚动条并能到达最后一项。
- 普通任务无论成功、需检查、失败、停止或保存并退出，队列真正结束后都重新展开设置；若

## 四、元数据工具执行设计

### 4.1 默认与预检

- 新建完整扫描的 ExifTool 与 ffprobe 模式默认均为 `complete`；兼容布尔字段仍为 `true`；
- 快速扫描拒绝显式元数据工具开关；
- 元数据阶段始终保留 7-Zip 结构解析能力；
- 关闭 ExifTool 时，不启动 ExifTool 常驻工作进程；
- 关闭 ffprobe 时，不执行音视频或 GIF 的 ffprobe 调用；
- 现行 GUI 扫描任务不调用格式校验或 RAW 深度校验；数据核验的工具预检与扫描元数据开关完全分离。

### 4.2 状态与报告

文件未被所选元数据工具处理且没有适用的其他解析器时，`meta_status` 使用现有允许值
`skipped`。这表示用户主动关闭或当前功能不适用，不是源文件损坏、工具故障或超时。
进度和完成摘要分别显示「跳过」，不并入「异常记录」。

工具真正运行后发生的 `source_error`（源文件问题）、`tool_error`（工具故障）和 `timeout`
（超时）仍沿用 v1.6.0 分类；连续同类工具故障达到阈值后停止相应阶段。本轮不削弱
ExifTool 会话重建、ffprobe 独立进程监督或连续故障保护。

### 4.3 续传与身份

两个逐工具范围写入 schema 4 的冻结 `config_json`。续传命令不允许覆盖，必须沿用未完成
快照中的值；旧未完成快照缺少逐工具范围键时，按既有全局 `metadata_storage` 和布尔工具开关解释。
新建 schema 4 快照文件名不再写入任何功能 token，只以 `Full`/`Quick` 区分模式；数据库
配置和运行清单 (`manifest`) 才是权威。运行清单记录实际选择，便于人工区分「0 个问题」与
「该工具未执行」。

## 五、兼容与安全审查

1. `SNAPSHOT_DDL`、schema 4 DDL、Diff DDL 和 STG schema 均不得修改；
2. 旧 schema 3 数据库只读前后 SHA-256 必须一致；
3. 冻结 schema 3 `full-scan`、`quick-scan` 脚本不增加新参数；
4. v1.6.0 schema 4 partial 缺少新配置键时默认启用两个工具；
5. v1.4.1/schema 3 数据库继续通过 Reader、Diff、档案数据核验、问题报告和档案数据解析回归；
6. 数据核验不能以「缺少格式校验字段」为由拒绝 v1.4.1 完整扫描库，不能迁移或回写输入库；
7. 用户明确授权目录内的 44 个真实 v1.4.1/schema 3 完整扫描样本均为 19 张表、complete、
   database_integrity=ok；后续兼容测试只允许 SQLite URI `mode=ro` 和 `query_only` 读取，
   不得修改或暂存这些样本；
8. 合成测试只写工作区 `.test_runtime` 或系统临时目录，不枚举、附加、终止或复用其他运行中进程；
9. 不执行真实硬盘检测；除用户明确授权的 v1.4.1 测试数据库目录外，不访问工作区外
   真实档案。
