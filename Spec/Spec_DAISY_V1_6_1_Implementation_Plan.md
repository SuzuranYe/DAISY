# DAISY v1.6.1 UI 与交互优化实施计划

- 目标版本：v1.6.1
- 状态：初步实现与仓库自动化验收完成；非稳定版，仍需真实环境长期验证
- 发布边界：只提交并推送 `Codex` 分支，不建立 `v1.6.1` tag
- 数据库兼容基线：v1.4.1／schema 3
- 上一数据契约：[v1.6.0 数据与恢复契约](Spec_DAISY_V1_6_0_Data_Contract.md)
- 测试证据：[v1.6.1 测试记录](Spec_DAISY_V1_6_1_Test_Record.md)

## 一、目标与边界

v1.6.1 是 v1.6.0 之上的 UI、交互和可选元数据采集优化，不升级 SQLite schema，
不修改 Diff 投影，不原地迁移任何旧数据库，也不改变冻结的 `full-scan`／`quick-scan`
schema 3 CLI 参数集合。普通“档案扫描”只负责建立数据库；格式、容器和 RAW 解码检查
全部归入独立“数据核验”，结果只进入报告或伴随输出，不回写封存数据库。

本轮只允许统一 `scan`／schema 4 新增两个冻结配置键：

- `metadata_exiftool: bool`；
- `metadata_ffprobe: bool`。

旧 schema 4 partial 缺少这两个键时必须按 `true` 解释，以保持 v1.6.0 默认行为。两个键只
决定元数据阶段是否调用对应工具，不新增表、列、索引或约束。扫描页不再提供格式校验或
RAW 深检选项；数据核验使用自己的工具选择，不复用扫描元数据开关。

## 三、界面结构

### 3.1 顶部功能入口

六列使用同一个 grid uniform group。每列权重相同，按钮使用相同样式、字符宽度、字体和
纵向内边距；每个按钮使用对称水平间距，避免最后一列比其它列多出一个间隔宽度。选中态
只改变颜色和样式名，不改变字体、padding、border 或 width。

### 3.2 扫描页两阶段交互

扫描页状态分为：

1. `scan_mode=""`：只渲染“扫描模式”行及两个模式按钮；运行校验必须提示选择模式；
2. `scan_mode="full"`：展开任务设置、扫描功能和 Full 从属设置；
3. `scan_mode="quick"`：展开任务设置和 Quick 允许的 File ID 设置，不渲染元数据或哈希
   控件。

Full 只保留建库所需的目录、生成方式、元数据、File ID、内容哈希及输出设置。Full 与
Quick 均不得渲染格式校验或 RAW 深检；这两项不能出现在扫描高级菜单或命令预览中。

Full 与 Quick 切换时先收集当前可见值，再在 Tk 事件返回后重建条件表单，避免销毁事件源
导致 Tcl/Tk 选择状态丢失。应用重启恢复上次页面和经过白名单过滤的非路径选项，但不持久
保存档案目录、数据库路径或输出路径；工具路径使用独立白名单保存。

### 3.3 二元按钮与校验工具行

- 二元按钮拥有固定字符宽度和固定 padding；开启为深绿白字，关闭为琥珀色深字；
- 元数据工具在同一行显示两个固定按钮，分别维护 ExifTool 与 ffprobe 布尔值；
- 数据核验的“校验工具”固定为一行五个按钮：`内置校验`、`ExifTool`、`ffprobe`、
  `7-Zip`、`RAW 深检`；
- 五个按钮使用相同高度、字符宽度、padding 和间距，状态变化只能改变颜色和文字，不能
  改变外框尺寸；
- 普通按钮组统一使用 8 px 水平间距；顶部六入口和文件选择按钮使用各自专用尺寸；
- 五项默认全部关闭。关闭时只执行不依赖这些工具的基础文件状态核对；开启后检查该工具
  全部适用文件，不提供抽样滑块；
- RAW 深检不可用时按钮禁用，并由悬停提示显示统一能力探测层返回的原因；其它工具只在
  被选择时参加预检。

### 3.4 数据核验板块

数据核验与数据库建立是两个独立功能板块。核验输入接受一个封存数据库及当前根目录映射，
只读取得 `roots`、`entries`、`hashes` 和快照身份；不能要求数据库含有历史校验字段。

各开关语义如下：

| 开关 | 适用内容 | 执行器 |
|---|---|---|
| 内置校验 | ZIP／OOXML 成员 CRC、PDF 头尾与交叉引用结构 | 隔离 Python 子进程 |
| ExifTool | 适用图片、RAW、GIF、音视频等的 `-validate` 诊断 | 受监督 ExifTool 子进程 |
| ffprobe | GIF、视频和音频的容器／流结构 | 受监督 ffprobe 子进程 |
| 7-Zip | 7z／RAR 等压缩包及旧 Office OLE 容器 | 受监督 7-Zip 子进程 |
| RAW 深检 | rawpy／LibRaw 支持的 RAW 实际解码 | 一次性隔离 Python 子进程 |

ExifTool 与 ffprobe 必须可以分别运行；选择 ffprobe 不能隐式启动 ExifTool，反之亦然。
同一文件可由多个已选择工具分别检查，报告保留各自结论。未识别、不支持或不适用的文件
类型只进入对应工具的统计，不写入问题列表。

### 3.5 下拉重复选择

`<<ComboboxSelected>>` 处理器必须优先读取 `Combobox.current()` 对应的稳定内部值。若新旧
内部值相同，立即恢复显示标签、清除编辑框选区，并在当前 Tcl/Tk 事件结束后的 idle 回调中
再校正一次；不得销毁或重建该控件。`TCombobox` 和 `Daisy.TCombobox` 必须显式覆盖普通、
只读、焦点、按下和禁用状态的前景色、选择前景色与选择背景色，不能继承 Windows 主题的
白色 `SystemHighlightText`。只有内部值真的变化时才延迟重建条件表单。

### 3.6 可选能力安装

- 软件安装区使用单排五列：ExifTool、ffprobe、7-Zip、smartctl、rawpy；所有按钮复用
  相同样式、字符宽度、padding 和 8 px 间距；
- 外部工具继续使用固定 WinGet 包 ID；rawpy 使用当前 GUI 所属 Python 执行
  `python -m pip install --upgrade --upgrade-strategy only-if-needed rawpy`；
- 安装命令只接受固定白名单名称，不接受任意包名；测试只模拟命令和确认框，不执行联网
  安装；
- 确认文案必须说明会修改当前 Python 环境和必要依赖。安装结束后运行 ENV-01，由统一能力
  探测层在独立子进程验证 rawpy／LibRaw；Tk 主进程不得导入 rawpy。

### 3.7 环境状态与目录选择

- 环境页按“检测状态 → 软件安装 → 报告目录”的顺序排列；
- 检测状态一行显示 ExifTool、ffprobe、7-Zip、PowerShell、smartctl、rawpy 六个等尺寸
  状态按钮；状态按钮只呈现已有内存证据，不因点击自行启动探测；
- 待检测、可用、缺失分别使用黄、绿、红三态，悬停显示完整版本、路径或不可用原因；
- 扫描和核验的“添加目录”均位于路径内容上方并从左侧起排；路径列表或映射框独占下一行；
- 无溢出判定允许 2 px Tk 几何取整容差，避免肉眼未溢出却出现空滚动；真实溢出仍必须
  显示滚动条并能到达最后一项。
- 普通任务无论成功、需检查、失败、停止或保存退出，队列真正结束后都重新展开设置；若
  处于小窗模式则先返回完整界面。依赖安装后的自动环境复检视为连续流程，仅在复检结束后
  展开，避免中途布局闪动。硬盘检测成功继续使用展开设置并收起进度／日志的专用选择布局。

## 四、元数据工具执行设计

### 4.1 默认与预检

- 新 Full 默认 `metadata_exiftool=true`、`metadata_ffprobe=true`；
- Quick 拒绝显式元数据工具开关；
- 元数据阶段始终保留 7-Zip 结构解析能力；
- 关闭 ExifTool 时，不启动 ExifTool stay-open worker；
- 关闭 ffprobe 时，不执行音视频或 GIF 的 ffprobe 调用；
- 扫描阶段不再调用格式校验或 RAW 深检；数据核验的工具预检与扫描元数据开关完全分离。

### 4.2 状态与报告

文件未被所选元数据工具处理且没有适用的其它解析器时，`meta_status` 使用现有允许值
`skipped`。这表示用户主动关闭或当前功能不适用，不是源文件损坏、工具故障或 timeout。
进度和完成摘要分别显示“跳过”，不并入“错误”。

工具真正运行后发生的 source error、tool error、timeout、熔断与恢复仍沿用 v1.6.0
分类；本轮不削弱 ExifTool 会话恢复、ffprobe 独立进程监督或工具级熔断。

### 4.3 恢复与身份

两个开关写入 schema 4 的冻结 `config_json`。恢复命令不允许覆盖，必须沿用 partial 中的
值；缺键按 `true` 解释。新建快照文件名可加入 `No-Exif`／`No-FFprobe` 提示 token，但
数据库内身份和 manifest 才是权威。manifest 记录实际选择，便于人工区分“0 个问题”与
“该工具未执行”。

## 五、兼容与安全审查

1. `SNAPSHOT_DDL`、schema 4 DDL、Diff DDL 和 STG schema 均不得修改；
2. 旧 schema 3 数据库只读前后 SHA-256 必须一致；
3. 冻结 schema 3 `full-scan`／`quick-scan` 脚本不增加新参数；
4. v1.6.0 schema 4 partial 缺少新配置键时默认启用两个工具；
5. v1.4.1／schema 3 数据库继续通过 Reader、Diff、核验、Issues 和数据库解析回归；
6. 数据核验不能以“缺少格式校验字段”为由拒绝 v1.4.1 Full 库，不能迁移或回写输入库；
7. 已经只读确认的 9 个真实 v1.4.1／schema 3 Full 样本结构一致且均无校验配置；后续只读
   兼容测试不得修改或暂存这些样本；
8. 合成测试只写工作区 `.test_runtime`，不枚举、附加、终止或复用其它运行中进程；
9. 不执行真实物理硬盘检测，不访问工作区外真实档案。
