# DAISY v1.5.1 测试计划

状态：已完成
制定日期：2026-08-06
目标版本：v1.5.1
执行分支：`Codex`

本计划用于验证 v1.5.1 的 UI、交互和人读报告优化，同时证明数据库扫描、
数据库生成、Diff、schema、profile 与 data contract 没有发生非预期变化。
技术语义以 [技术规格](Spec_DAISY_Technical.md) 为准，版本结论回填到
[版本演进](Spec_DAISY_Version_Evolution.md)。

## 1. 测试边界

### 1.1 本轮覆盖

- 默认 1080P、固定布局、小窗往返、视图菜单和面板展开／收起。
- 全任务页滚动边界、字体、字号、窗口尺寸、宽高比和 Tk 缩放组合。
- 按钮、下拉框、提示框、日志窗口、进度区和关闭确认的交互。
- 六字以内字段命名、固定标签基线、右侧操作列和无必填星号呈现。
- 正常关闭与管理员重启后的页面恢复，以及不保存表单内容的隐私边界。
- 硬盘检测开始、成功、无可选硬盘和失败四种 UI 状态转换。
- Excel 人读报告、技术 CSV、随 SQL 输出的 `Issues.md`。
- Tcl/Tk 运行时修复和两个 GUI 入口。
- v1.4.1 数据库核心契约与 v1.5.1 版本标识。

### 1.2 明确不做

- 不把本轮 UI 优化扩展成数据库扫描、Diff 或数据库生成算法重构。
- 不为了 UI 测试运行真实档案扫描、真实硬盘检测、WinGet 安装或缓存清理。
- 不把“未实际识别的文件格式”从数据库证据中删除；只允许改变
  `Issues.md` 的人读筛选。
- 不以截图“看起来正常”替代控件几何、状态和可达性断言。

## 2. 进程与数据隔离

当前机器有其他进程运行，以下规则是本计划的硬约束：

1. 不枚举、不停止、不挂接、不复用其他进程，也不按进程名执行终止操作。
2. Tk 测试只建立当前测试进程内的透明窗口，并在每个用例后取消回调、销毁窗口。
3. 若入口测试必须创建子进程，只允许管理测试自己创建且可精确识别的 PID；
   本轮优先采用进程内自动关闭入口，不创建常驻 GUI。
4. 数据测试只使用 `tempfile` 目录和合成夹具，不读取用户档案或真实硬盘内容。
5. 硬盘检测 UI 使用模拟 `storage_inventory` 事件和退出码；不调用 Windows
   存储查询或 `smartctl`。
6. 安装按钮只验证布局、文字、状态和命令白名单，不调用 WinGet。
7. GUI 设置读写重定向到临时文件，不改动用户正在使用的运行时设置。

任一测试违反以上边界，整轮测试立即判定失败。

## 3. 发布门槛

v1.5.1 只有同时满足以下条件才可验收：

- G1：语法编译、目标单测、真实 Tk UI 矩阵和完整回归全部通过。
- G2：关键 Tk UI 套件连续运行 3 轮均通过，且没有 Tcl 回调残留错误。
- G3：所有默认 1080P 页面内容完整；未溢出页面无法滚动，溢出页面首尾可达。
- G4：所有可点击控件文字不裁切、热区有效；下拉框无重复选择消失问题。
- G5：硬盘检测的成功与失败状态转换符合预期，且没有运行真实检测。
- G6：中文人读报告可由 Excel 原生打开；技术 CSV 契约有明确且经过测试的边界。
- G7：`Issues.md` 筛选不改变 SQLite 中的 issue 记录。
- G8：数据库 schema、profile、data contract、最低读取版本和核心回归全部通过。
- G9：版本号、文档、代码和测试对 v1.5.1 的描述一致。
- G10：工作区文本保持 UTF-8 无 BOM 与 LF；有意采用其他封装格式的二进制
  文件除外。

## 5. UI 组合矩阵

### 5.1 被测页面

每个矩阵组合覆盖以下页面，而不是只抽测主页：

1. ENV-01 运行环境检测。
2. DBS-91 DAISY 功能自检。
3. DBS-11 完整档案扫描。
4. DBS-12 快速档案扫描。
5. DBS-21 快照变更分析。
6. DBS-31 内容哈希核验。
7. DBS-32 文件结构核验。
8. DBS-41 结果报告导出。
9. STG-11 硬盘信息登记。

### 5.2 维度

| 维度 | 取值 |
| --- | --- |
| 字体族 | 当前机器实际安装且出现在 DAISY 设置菜单中的全部候选字体；不得少于 2 种 |
| 字号 | 标准、较大 `+1`、特大 `+2` |
| 设置预设 | 1920×1080、1600×900、1366×768 |
| 手动尺寸／比例 | 1840×1020、1440×900 `16:10`、1280×720 `16:9`、1280×960 `4:3`、1280×1024 `5:4`、1100×850、1024×768 |
| Tk 相对缩放 | 启动值的 100%、125%、150%，每轮结束恢复启动值 |
| 页面数据状态 | 空白默认值、条件字段切换后、硬盘清单有可选项、硬盘清单无可选项 |
| 面板状态 | 设置展开；设置收起＋进度／日志展开；小窗；小窗返回完整界面 |

执行分两组，防止只做低覆盖的配对测试：

- M1 全量几何矩阵：字体族×3 级字号×7 个窗口尺寸／比例×9 个页面。
- M2 缩放矩阵：3 级相对缩放×3 级字号×至少 4 种宽高比×9 个页面。
- M3 交互矩阵：每页的所有下拉框、可安全触发的面板按钮、提示目标和状态转换。

### 5.3 每个页面组合的自动判据

每个 M1／M2 组合都必须检查：

1. 根窗口、顶部导航、设置、进度、日志、命令区不重叠且不越出客户区。
2. 页面标题与说明非空；实际高度不小于其请求高度，允许按设计换行但不能裁切。
3. 表单 Canvas 宽度大于最小可用值，字段标签和输入控件不发生横向截断。
4. 按钮和下拉框实际宽度不小于请求宽度；按钮文字可完整显示。
5. 内容高度不超过视口时：滚动条隐藏，`yview == (0.0, 1.0)`，上下滚轮均不移动。
6. 内容高度超过视口时：滚动条显示；滚到底部可看到内容末端；连续向上滚动后
   `yview[0] == 0.0`，顶部没有空白。
7. 从长页面滚到底部再切到短页面，短页面必须回到顶部且滚动条隐藏。
8. 改字体、字号、尺寸或缩放后立即重算滚动范围，不使用旧页面的 `scrollregion`。
9. 所有自定义下拉箭头的图形可见、热区不少于 `20px`，控件右侧点击可命中箭头元素。
10. Tk 回调队列可清空；销毁窗口时不得出现 `invalid command name`、
    `TclError` 或残留计时器错误。

## 6. 功能用例

### 6.1 静态与纯逻辑测试

- UT-01：GUI 与测试文件通过 `py_compile`。
- UT-02：视图菜单标签、顺序和小窗动作与状态同步。
- UT-03：开始任务前依次收起设置、展开进度、展开日志，再启动队列。
- UT-04：硬盘检测的任务键、进度文案和事件负载解析正确。
- UT-05：窗口、字体、字号、空闲关闭偏好以 UTF-8 无 BOM、LF 持久化；非法值回退。
- UT-06：所有页面说明保持约定长度，默认 1080P 下为统一高度。
- UT-07：哈希报告默认目录仅用于展示，不破坏后端自动命名；自定义文件仍传 `--report`。
- UT-08：空闲关闭遵循设置；运行／启动过程中即使关闭确认被禁用，也必须弹出确认。
- UT-09：全部页面字段、顶部工具字段和分区标题最多 6 个字符；必填属性仍保留，
  但可见标题不包含星号。
- UT-10：偏好只保存合法的 `last_task_key`；不得写入 `saved_values`、路径、硬盘编号
  或其它表单参数。内部列盘页和非法页面键回退到环境检测页。

### 6.2 真实 Tk 几何与交互

- TK-01：默认有效工作区约 1840×1020 时，9 个页面全部无需滚动。
- TK-02：设置、进度、日志、命令位于固定 grid 行，且不存在 `PanedWindow`／拖动柄。
- TK-03：进入小窗后仅保留规定区域；返回后四个固定面板全部恢复且几何完整。
- TK-04：执行 M1、M2 矩阵和面板边界断言。
- TK-05：短页面连续上下滚轮各 100 次，位置始终为顶部且滚动条隐藏。
- TK-06：长页面滚到底、回到顶、再切短页面，验证首尾和状态重置。
- TK-07：以 ENV-01、DBS-11、STG-11 分别验证不同内容高度与条件字段重建。
- TK-08：独立日志窗口单例、初始复制、实时追加、清空同步、关闭引用释放，默认高度足够。
- TK-09：运行态设置标题折叠；进度和日志展开；日志获取剩余高度；命令区贴合底边。
- TK-10：模拟硬盘检测开始、成功、有盘无可选盘、失败；验证弹窗与面板状态；
  成功后再模拟“开始任务”，确认重新进入运行布局。
- TK-11：目录添加、浏览、硬盘全选／取消、检测、安装按钮使用统一样式和尺寸层级。
- TK-12：四个安装按钮同一行、等列宽，字体变化后文字仍完整。
- TK-13：字段标签、整个字段单元和控件均可触发同一提示；提示保持在显示器工作区内。
- TK-14：对每个下拉框重选当前项，文本和控件不消失；切换其他项后重建控件且值正确。
- TK-15：样式布局不含原生 `Combobox.downarrow`，使用细线 V 形下箭头；透明热区与像素图形分离。
- TK-16：内容哈希核验默认报告位置在控件中可见。
- TK-17：设置字体／字号／窗口后立即生效；重建表单与独立日志窗口继承设置。
- TK-18：逐字体、逐字号切换全部功能页，所有字段标题右边界和输入区左边界保持唯一；
  列表型与映射型“添加目录”以及浏览按钮都位于右侧操作列。
- TK-19：以指定最后页面构造新 Tk 应用，确认返回该页面，同时输入框、目录映射和
  内存表单缓存保持空白；管理员重启路径在启动新进程前保存同一页面键。

### 6.3 报告输出

- RPT-01：生成包含中文路径、中文 issue 和中文摘要的 `Report_Excel.xlsx`，解析 OOXML
  验证中文原样、中文工作表名、冻结首行、筛选和列宽。
- RPT-02：CSV 保留完整技术字段、UTF-8 无 BOM 与 LF；面向 Excel 的入口和说明明确指向
  原生 Unicode XLSX，避免依赖 Excel 对无 BOM CSV 的本地编码猜测。
- RPT-03：构造“仅格式不认识”与真实错误混合夹具；`Issues.md` 只隐藏精确命中的
  格式伪问题，其他 issue 仍输出。
- RPT-04：超长单元格在 XLSX 中安全截断，但 CSV 技术数据不被修改。
- RPT-05：快照报告与 Diff 报告都执行中文、文件集合和摘要一致性检查。

### 6.4 STG 与硬盘 UI

- STG-01：从归档生成代码和夹具 ZIP 核对三个 JSON 的精确文件名、来源和职责。
- STG-02：Windows 查询脚本不包含变更存储状态的 cmdlet；smartctl 命令只使用只读参数。
- STG-03：归档夹具测试覆盖 JSON 哈希、成员清单、篡改检测和 schema 版本。
- STG-04：本轮不执行真实列盘；UI 成功／失败通过事件夹具验证。

### 6.5 Tcl/Tk 与入口

- GUI-01：清除会干扰判断的进程内 Tcl/Tk 环境变量后，通过 DAISY 引导建立透明 Tk 根窗口，
  核对 Tcl/Tk 版本并自动销毁。
- GUI-02：分别走 `Script_DAISY_GUI.py` 和 `Script_DAISY_MAIN.py` 的 GUI 构造入口，
  注入自动关闭回调；不得启动扫描或常驻子进程。
- GUI-03：连续构造／销毁窗口，确认 Tcl 库路径不会污染或破坏后续实例。

### 6.6 数据库零回归

- DB-01：核对 `schema_version=3`、元数据 profile、data contract、最低读取器版本和 DDL。
- DB-02：运行快照生成、封存、快速扫描、完整扫描夹具与 Diff 黄金测试。
- DB-03：同一夹具在生成 `Issues.md` 前后查询 SQLite，issue 行数和内容完全一致。
- DB-04：运行不可覆盖测试，核对旧文件 SHA-256、`snapshot_uuid` 和临时残留。
- DB-05：审查本轮 diff，数据库路径只允许版本标识和 `Issues.md` 渲染边界的预期改动；
  扫描、Diff、生成、DDL 和 schema 代码不得发生 UI 需求之外的改动。

## 7. 重复执行策略

为发现 Tk 时序和几何抖动，测试不只运行一次：

1. 修改过程中，每个相关目标用例在修复后立即运行。
2. 关键 UI 套件连续运行 3 轮；任一轮失败即回到修复阶段，计数重新开始。
3. M1 全量矩阵至少完整运行 2 轮；M2 缩放矩阵至少完整运行 2 轮。
4. 完整自动化回归在代码冻结前运行 1 轮，版本／文档更新后再运行 1 轮。
5. 最终语法、编码、换行和 git diff 检查再独立运行 1 轮。

不得通过增加重试来掩盖非确定性失败。若同一用例偶发失败，必须记录回调、几何或状态根因。

## 8. 失败分级与修复规则

- P0：影响其他进程、写入真实用户数据、数据库契约变化。立即停止测试并回滚相关改动。
- P1：GUI 无法启动、控件不可点击、内容不可达、中文报告不可读。阻止发布。
- P2：文字裁切、布局错位、滚动空白、状态转换错误。阻止发布。
- P3：轻微视觉不一致但不影响可读与操作。修复后重新执行相关矩阵。

每次失败记录“预期、实际、组合维度、最小复现、根因、修复、重测范围”。
