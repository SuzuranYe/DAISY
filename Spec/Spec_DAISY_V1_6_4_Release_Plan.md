# DAISY v1.6.4 长期生产版本发布计划

- 目标版本：v1.6.4
- 发布性质：长期生产版本
- 长期生产谱系：v1.4.1 → v1.6.4
- 发布基线：v1.6.3 发布提交 `70afc7cb99292f86ddf2630bc248eec9e8d4500b`
- 当前状态：发布门禁通过，待提交与推送
- 数据兼容基线：v1.4.1/schema 3 FULL 封存快照

## 一、版本定位

v1.6.4 是继 v1.4.1 后第二个明确适合长期部署、并作为后续兼容维护基线的生产版本。
「生产版本」是本项目的长期维护级别，不否定 v1.5.0～v1.6.3 的历史发布和标签；这些版本
仍是有效历史节点，但不计入长期生产谱系。

v1.6.4 继承 v1.6.3 的全部功能，收敛核验页环境能力状态、若干按钮尺寸与布局、窗口预设
顺序和界面文案，并更新应用版本。它不扩展数据库扫描、建库、Diff、哈希、元数据、格式
核验、数据库解析或硬盘归档的数据协议。

## 二、本版变更

1. 当前会话尚未完成运行环境检测时，档案数据核验显示「需要先运行环境检测」。
2. ExifTool、ffprobe、7-Zip 和 rawpy/LibRaw 在检测前灰显；基本校验仍明确为内置能力。
3. 检测前点击开始由参数预检拒绝，避免默认选择被误认为工具已经通过检测。
4. 检测完成后，ExifTool、ffprobe 和 7-Zip 只按已验证工具清单启用；rawpy/LibRaw 只按
   隔离运行能力结果启用。不可用项目保持灰色，并在悬停说明中显示原因。
5. 暂时灰显只影响本次可执行值，不覆盖用户保存的请求状态；能力恢复后按原选择恢复。
6. 「重置软件」清除本次环境清单状态，核验页重新回到待检测状态。
7. DBS `SCANNER_VERSION` 与 STG `APP_VERSION` 更新为 `1.6.4`。
8. 底部「打开结果目录」按钮缩短为「产出」；功能、命令、配色、悬停说明和完成提示不变。
9. 待检测信息改为与硬盘登记管理员状态相同层级的琥珀色提示卡；硬盘选择区的
   「全选／取消选择」改为与「浏览」相同的小按钮尺寸和样式。
10. 「管理员模式」改为与「收起设置／展开进度」相同尺寸，并与权限状态标题纵向居中。
11. 「管理员模式」在 X 轴对齐设置标题栏倒数第二个「恢复默认」按钮。
12. 窗口大小预设按分辨率升序排列；「结果目录提示」改名为「结果目录弹窗」，不改变
    默认值、配置键或任务结束行为。

## 三、冻结数据与兼容边界

- 旧版 DBS `SCHEMA_VERSION=3`、统一扫描 `SCHEMA_VERSION=4`、STG
  `ARCHIVE_SCHEMA_VERSION=3`、元数据 `PROFILE_VERSION=7` 保持不变。
- v1.4.1/schema 3 FULL 封存库继续由统一 Reader 只读打开；不得迁移、补列或回写旧库。
- 冻结的 `full-scan`、`quick-scan`、`check-hash`、`check-format` 和 `export-report`
  兼容入口及其参数保持不变。
- 统一扫描、恢复、Diff、核验、解析、问题报告和 STG Manifest 的结构契约保持不变。
- 应用版本变化只更新新产物记录的程序版本，不代表数据库或归档结构升级。
- v1.4.1 程序不承诺读取 schema 4；v1.6.4 也不接管 v1.4.1 未封存的工作快照。

## 四、生产发布门禁

1. 运行完整发现式自动化套件，所有警告按错误处理。
2. 运行 v1.4.1 FULL 的 13 个 Reader／Diff／核验／问题报告／解析专项模块。
3. 对用户授权的真实 v1.4.1 FULL 数据库目录执行只读识别和兼容审计；检查前后字节数与
   mtime 不得变化，测试输出只能进入系统临时目录并在结束后回收。
4. 运行现行核验环境门控的真实 Tk 定向测试，覆盖首次提示、灰色禁用、检测后启用、
   不可用原因、保存选择恢复和重置状态；同时验证「产出」在空闲、运行、暂停状态下保持
   原有命令、位置、尺寸和两次绿色提示，并验证提示卡层级及硬盘选择小按钮的实际尺寸。
5. 验证「管理员模式」与面板收起／展开按钮实际宽高一致、与权限状态标题中心线对齐，
   并在 X 轴对齐「恢复默认」；验证窗口预设顺序和「结果目录弹窗」文案。
6. 检查 Python 源码可编译、PowerShell 脚本可解析、`git diff --check`、UTF-8 无 BOM、
   LF、Markdown 相对链接和禁止 Wiki／Obsidian 双方括号链接。
7. 确认没有修改 DBS／STG DDL、数据库扫描实现、Diff 算法或冻结兼容入口。
8. 把全部命令、数量、耗时、边界和已知限制写入
   [v1.6.4 测试记录](Spec_DAISY_V1_6_4_Test_Record.md)。

任一门禁失败都必须先修复并重跑；不得把部分通过描述为生产版本验收通过。

## 五、发布流程

- 用户已明确授权运行全量测试并把成果推送为 v1.6.4。
- 所有发布修改先提交到 `Codex`；获取远端引用后确认 `origin/main` 和 `origin/Codex`
  没有出现未预期分叉。
- `main` 只允许快进到已验收的 `Codex` 提交；禁止强推、合并提交或改写已有标签。
- 创建注释标签 `v1.6.4`，标签说明为 `DAISY v1.6.4`。
- 使用一次原子推送更新 `Codex`、`main` 和 `v1.6.4`；推送后重新获取并核对
  `origin/Codex == origin/main == v1.6.4^{}`。
- 已有 `v1.6.3` 标签和历史提交保持不变。
