# DAISY v1.6.0 数据库解析设计

状态：已实现；本文只保留长期有效的设计与行为边界

目标版本：v1.6.0

对应版本：v1.6.0

阅读说明：本文保留 v1.6.0 当时的「数据库解析」名称。自 v1.6.2 起，现行 GUI 功能名为
「档案数据解析」，识别动作为「解析数据库」；现行术语以
[技术规格](Spec_DAISY_Technical.md#11-用户可见文字规范)为准。

## 一、功能定位

DBS-41 更名为「数据库解析」，用于只读识别数据库能力、选择数据模块并导出指定格式。
它不再把「导出数据库表」和「给人看的报告」混为一件事：

1. **人读报告**回答数据库是什么、是否完整、包含什么、哪里需要关注，以及 Diff 中发生
   了什么变化。默认产物为自包含 `Report.html`。
2. **分析工作簿**供人在 Excel 中筛选、排序和交叉查看选中的数据。产物为
   `Report_Excel.xlsx`。
3. **技术数据导出**保存稳定字段名和完整值，供脚本、审计与二次分析。产物为所选模块
   的 UTF-8 无 BOM、LF CSV 或流式 JSONL。

SQLite 仍是完整事实来源。HTML、XLSX、CSV 都是可重新生成的投影，不得回写输入库，也
不得用显示层推断替换数据库原始证据。

## 二、当前实现需要解决的问题

- GUI 要求用户先手工判断「封存快照」或「Diff 数据库」，选错后才报错。
- 快照导出没有真正的摘要报告，只生成全部技术 CSV，再把 CSV 原样转换为 XLSX。
- `Report_guide.csv` 被当作人读入口，但它本身仍需要用表格软件打开。
- 用户不能选择需要的模块，包含 0 行或完全不关心的表也会导出。
- 多处查询通过 `fetchall()` 把整表载入内存，不适合大型快照或 Diff。
- 输出目录使用固定名称且可复用，旧报告存在时可能被新文件逐项覆盖并混合。
- XLSX 有中文字段和筛选，但缺少结论首页、问题优先级、覆盖率和建议操作。
- CSV 是机器接口，却容易被误当成人读入口；Excel 双击时既有编码误判风险，也需明确
  防范公式注入。

## 三、GUI 工作流

### 3.1 初始状态

- 页面只显示「选择数据库」「报告目录」和简短用途说明，不要求用户选择数据库类型。
- 「选择数据库」与硬盘页的「选择硬盘」使用相同高度、内边距、图标、悬停提示和状态色。
- 未识别数据库前，模块和格式区显示占位说明，开始按钮禁用。

### 3.2 自动识别

选择 `.sqlite` 后执行两阶段只读检测：

1. 快速识别 `sqlite_master`、`snapshot_info`／`diff_info`、schema、生成器版本、封存状态、
   文件大小、可用表列和模块行数；不得访问数据库内记录的源文件路径。
2. 导出前执行可取消的 `quick_check`／外键检查。快速识别可以先展示选择界面，但完整性
   尚未通过时必须清楚标记，不能提前表示数据库健康。

检测开始后展开进度与日志。成功后弹出简短结果，展开设置并收起进度／日志，行为与
STG 硬盘识别完成后的选择阶段一致；失败时保留日志和进度诊断。

识别区至少显示：

- 数据库类型：完整快照、快速快照或 Diff；
- 数据库文件名、大小、schema、生成器版本和 UUID；
- 扫描／生成状态、声明完整性和实际只读检查状态；
- v1.4.1 兼容模式或 v1.6.0 原生模式；
- 可用模块数、空模块数和不可用模块数。

更换数据库必须取消旧检测、清空旧模块选择和统计，再根据新库重新建立状态；不得让上一个
数据库的勾选泄漏到新任务。

### 3.3 模块选择

模块使用与硬盘候选卡一致的复选卡网格。卡片包含六字以内标题、记录数、短说明和能力
状态；整张卡片均可点击，悬停在标题或说明上都能显示完整提示。

快照模块：

| 稳定 ID | 标题 | 内容 |
|---|---|---|
| `overview` | 数据概览 | 身份、根目录、时间、数量、容量、状态和覆盖率 |
| `issues` | 问题摘要 | 错误、待复核候选、枚举缺口和性能候选 |
| `files` | 文件清单 | 文件路径、类型、大小、时间和处理状态 |
| `directories` | 目录清单 | 目录树和枚举状态 |
| `hashes` | 逐文件哈希 | 每个文件的 SHA-256、来源、读取量和状态 |
| `photo_metadata` | 照片信息 | 照片规范化元数据 |
| `video_metadata` | 视频信息 | 视频文件级元数据 |
| `video_gps` | 视频定位 | 规范化 GPS 点 |
| `media_streams` | 媒体轨道 | 视频／音频流信息 |
| `working_metadata` | 工作文件 | PSD、PSB、TIFF、PNG 等工作文件信息 |
| `document_metadata` | 文档信息 | PDF／Office 文档信息 |
| `archives` | 压缩归档 | 压缩包和成员摘要 |
| `raw_payloads` | 原始数据 | ExifTool／ffprobe canonical JSON 原始载荷及来源证据 |
| `diagnostics` | 诊断证据 | 错误与元数据诊断原始记录 |
| `run_history` | 运行历史 | manifest、run session、事件和工具来源 |

Diff 模块：

| 稳定 ID | 标题 | 内容 |
|---|---|---|
| `overview` | 对比概览 | 双侧身份、覆盖率、root 配对和双维度结论 |
| `file_changes` | 文件变化 | added、deleted、changed、moved、copied 和证据等级 |
| `directory_changes` | 目录变化 | 目录增删及状态变化 |
| `content_groups` | 内容分组 | 哈希多重集、副本数量和硬链接变化 |
| `enumeration_gaps` | 枚举缺口 | 失败子树、影响范围和 unknown 传播 |
| `evidence_notes` | 证据说明 | 证据等级、能力缺失和兼容降级说明 |

能力状态为：

- `available`：有能力且有记录，可以勾选；
- `empty`：结构存在但为 0 行，显示「无记录」，默认禁用；
- `unavailable`：旧 schema 没有该能力，显示「此数据库未记录」，不得显示为 0；
- `incompatible`：结构存在但当前读取器无法安全解释，阻止相关模块而非让整个程序崩溃；
- `invalid`：数据库身份、封存状态或完整性不合格，阻止全部导出。

「全选／取消选择」只作用于 `available` 模块，按钮保持紧凑并与全局设计一致。

### 3.4 预设与格式

内容预设：

- 「人读摘要」（默认）：概览、问题和高层组成统计；大表只提供有限预览。
- 「完整审计」：选择全部可用模块。
- 「自定义」：保留用户当前逐项选择。

格式复选项彼此独立，并根据所选模块显示兼容状态：

- 「网页报告」默认开启；
- 「Excel 工作簿」默认关闭；
- 「技术 CSV」默认关闭；
- 「JSONL 原始数据」默认关闭，只对支持结构化逐行输出的模块启用。

至少选择一个模块和一种与之兼容的格式才能开始。逐文件哈希和格式化元数据支持
HTML 预览、XLSX、CSV、JSONL；原始载荷完整导出优先使用 JSONL，HTML／XLSX 只提供
受限预览，不能把超长 JSON 强塞进 Excel 单元格。选择「完整审计」不应隐式开启某种
格式；内容和格式是两个不同维度。

### 3.5 运行状态

点击「开始导出」后收起设置，展开进度与日志，并显示当前模块、已处理行数和总模块进度。
取消只停止本窗口创建的导出任务。失败、取消或冲突时保留可诊断日志，不发布半成品；成功
后提供「打开报告」和「打开目录」，默认打开 `Report.html`，其次为 XLSX。

## 四、人读 HTML 信息架构

### 4.1 共用首页

`Report.html` 为单个自包含 UTF-8 文件，不加载网络字体、CDN、遥测或远程脚本。首页依次
展示：

1. 报告结论与数据库健康状态；
2. 数据库身份、生成器、schema、扫描时间和报告时间；
3. 根目录、文件数、目录数、总容量和类型组成；
4. 哈希、元数据、枚举和可选结构校验覆盖率；
5. 需要处理的问题和待复核候选；
6. 已选择模块的摘要和预览；
7. 兼容降级、证据不足、完整技术数据位置和隐私说明。

不得用「存在问题=1」表达人工结论，应显示受影响文件数。状态值使用中文展示，同时保留
原始机器值供复制。

Issues 预览沿用固定证据域板块：枚举、哈希、Exif／元数据、格式校验、读取性能候选和
运行／证据。已执行且没有问题显示 `0`；未执行、旧库未记录或不适用显示 `NULL` 和原因，
不能把缺少能力显示为「通过」。

### 4.2 快照视图

- 按 root、媒体类型和扩展名汇总文件数量与容量；
- 展示最大文件、哈希覆盖、处理状态和高信号诊断；
- unsupported／unknown format 只显示去重总数，不展示路径或逐类型明细；
- 普通 warning／validation 折叠，严重损坏候选优先；
- 大表默认预览前 200 行，必须显示总数和完整 XLSX／CSV 是否已导出。

### 4.3 Diff 视图

- 内容维度与结构维度分开给出结论；
- added、deleted、content changed、stat changed but content same、moved、copied、unknown、
  hash missing 和 unstable 分开统计；
- 枚举失败子树和证据不足置于普通变更列表之前；
- 显示 root 配对、双侧哈希覆盖、同次计算沿用和跨 schema 降级；
- 只预览最需要处理的变更，完整列表进入选中的 XLSX／CSV 模块。

### 4.4 显示与安全

- 提供固定目录、折叠章节、客户端表内文本筛选、打印 CSS 和窄窗口响应布局；不绘制对
  结论没有帮助的装饰性图表。
- 所有数据库文本进行 HTML 转义；内嵌脚本使用严格 CSP，不执行数据库内容，也不自动
  打开数据库记录的路径。
- 路径默认可选中复制但不生成 `file://` 链接，避免报告打开时意外访问源档案。
- 预览数据量必须有固定上限，搜索只覆盖已嵌入预览；不得把数十万行 JSON 隐藏在 HTML
  中伪装成轻量报告。

## 五、XLSX、CSV 与 JSONL

### 5.1 XLSX

- 首张工作表固定为「报告概览」，包含结论、身份、覆盖率、问题数、所选模块和阅读说明；
- 后续工作表只包含用户勾选的模块，使用中文工作表名和「中文名\n(原字段名)」表头；
- 冻结表头、启用筛选、设置语义列宽，超过 1,048,576 行自动分表并显示总行数；
- 超过 32,767 字符的显示值可以截短，但概览和相邻说明必须指向保存完整值的 CSV；
- 所有输入值按字符串或明确数值类型写入，文件名和元数据不得被解释为公式。

### 5.2 CSV

- 只导出用户勾选模块，每个模块一个稳定文件名；
- UTF-8 无 BOM、LF、RFC 4180 引号规则，表头保持稳定机器字段名；
- 不为适配 Excel 而加入 `sep=`、本地化字段或修改原始值；
- 在独立 `Report_manifest.json` 中记录工具身份、输入数据库 SHA-256、模块、SQL 投影版本、
  行数、字段、文件 SHA-256、兼容降级和生成时间；
- 明确标注 CSV 是技术接口。若用户选择「Excel 工作簿」，应优先打开 XLSX，而不是 CSV。

### 5.3 JSONL 与原始载荷

- `raw_payloads.payload_zlib` 按行解压，并校验 `uncompressed_bytes` 与
  `payload_sha256`；不匹配时输出明确的解析错误，不能静默跳过或伪造 JSON。
- 每行包含数据库身份、root、相对路径、provider、provider_version、payload SHA-256
  和一个 JSON 值；保持 canonical JSON 的类型，不把嵌套对象压平为不稳定列集合。
- 逐文件哈希和规范化元数据也可输出 JSONL，字段使用稳定模块投影，不直接泄漏 SQLite
  内部 row ID 作为跨数据库身份。
- 原始载荷可能包含位置、设备、软件和作者信息。勾选时显示额外隐私提示；HTML 只显示
  受限、转义后的预览，完整 JSONL 不嵌入浏览器报告。

## 六、数据库识别与 v1.4.1 兼容

- v1.6.0 必须识别并只读导出 v1.4.1 完整 schema 3 快照和 Diff 数据库；不得要求旧库
  先迁移，也不得因缺少 v1.6.0 新表而拒绝其它可用模块。
- 识别依据为数据库身份表、schema、实际表列和状态组合，不能只比较生成器版本字符串。
- 所有模块通过稳定 capability adapter 查询。旧库缺少新字段时标记 `unavailable`，不能
  用 0、空字符串或「正常」填充。
- 输入连接使用只读 URI；检测和导出前后验证输入 SHA-256 相同。不得对旧库执行 PRAGMA
  journal 模式切换、VACUUM、迁移或临时索引创建。
- 工作区 `TEMP` 中的真实 v1.4.1 数据库仅用于额外只读观察；正式测试使用去隐私的固定
  schema 3 金样，不依赖用户文件，也不访问其记录的源路径。
- 新增 `parse-db --database`、`--preset`、`--include` 和 `--format` 统一接口；保留现有
  `export-report --snapshot` 和 `--diff` 作为兼容包装。旧参数的默认输出在过渡期必须有
  明确迁移提示，不能静默改变脚本所依赖的技术 CSV 字段。

## 七、脚本合并与职责边界

- 抽出统一只读数据库检查器，负责类型、schema、表列、能力和 v1.4.1 fallback；GUI、
  Issues、Diff、核验和解析不得各写一套相互漂移的准入 SQL。
- 建立稳定模块投影注册表，每个模块声明 ID、适用数据库类型、所需能力、字段、流式查询、
  支持格式和兼容降级。格式写入器只消费投影行，不直接拼业务 SQL。
- HTML、XLSX、CSV、JSONL 分别实现流式 writer，共用转义、公式防护、超长值、行数统计、
  取消和 manifest 逻辑；不得继续把所有实现堆入单个 DBS-41 Module 脚本。
- DBS-41 模块负责两类参数解析和编排；`parse-db` 使用统一 Reader、模块目录和新版执行层，
  `export-report` 在同一模块中保留薄兼容路径并调用冻结 writer。两者不能强行共用同一个
  输出 writer，否则无法同时满足新版模块选择和旧 CSV／XLSX 字节契约。
- 先以兼容层证明现有 v1.5.1 输出投影不变，再逐步切换 GUI 和新增格式；不能在一次提交
  中同时重写 SQL、格式和界面而失去可定位的回归边界。

## 八、性能、取消与发布

- 表数据通过游标分批流式写出，禁止对完整 `entries`、`metadata_diagnostics`、
  `diff_entries` 等大表调用 `fetchall()`；HTML 统计使用 SQL 聚合和受限预览。
- 每种格式写入同一输出目录下的唯一 staging 目录，所有文件关闭、校验并生成 manifest
  后再 no-clobber 原子发布为 `<数据库基名>_Report_<UTC时间>`。
- 取消在批次边界检查，并通过 SQLite progress handler 中断长查询；只清理由本次任务创建
  且已经验证位于 staging 下的文件，不触碰旧报告或其它进程文件。
- 同一数据库的一次导出使用一致只读事务，避免多个模块观察到不同外部状态；输入为完整
  封存数据库时不应出现写入竞争。
- 进度以模块数和已输出行数表达，不用不确定动画冒充数据进度；无法预先获得精确总行数
  时明确标记「已处理 N 行」。
