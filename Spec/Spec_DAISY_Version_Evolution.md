# DAISY 更新日志（v1.0.2～v1.5.1；含 v1.5.2 计划）

- 当前版本：**DAISY v1.5.1**。
- 更新日期：**2026-08-06**。
- 日期来自现存历史记录和 Git 检查点；`v1.2.0` 只能确认是设计过渡点，不能写成已确认的正式发布。
- 当前数据和运行语义见[技术规格](Spec_DAISY_Technical.md)。

## 2026-07-18 — Kit_AL v1.0.2

- 新增：形成纯本地、源目录只读的档案证据工具；提供 Full、Quick、哈希校验、格式校验、Diff 和报告导出。
- 新增：以 SQLite 保存文件树、时间、规范化元数据、Raw Payload、File ID、SHA-256、压缩包成员和错误记录。
- 改进：补齐统一入口、Diff 自动 root 配对、逻辑路径和进度节流；现存记录可证明当日已用于 TB 级真实目录。
- 删除：没有发现可核实且属于本版本的删除项。

## 2026-07-21～22 — Kit_AL v1.0.3

- 改进：根据 4 组真实机械硬盘运行记录区分 3.5 英寸 HDD 与 2.5 英寸移动 HDD 的表现。
- 修复：把 Quick、元数据和哈希阶段的性能描述改成受文件数量、目录形状、格式组合与介质影响的实测口径。
- 删除：移除缺少证据的统一速度和规模承诺；schema、算法和产物语义不变。

## 2026-07-26 — Kit_AL v1.1.0

- 新增：加入不依赖第三方 Python 包的 Tkinter／ttk GUI，覆盖全部业务任务。
- 新增：提供路径选择、参数校验、命令预览、后台子进程、实时日志、停止控制和结果目录入口。
- 改进：GUI 保持为统一 CLI 的薄前端，不复制扫描、哈希或 Diff 逻辑。
- 删除：没有发现可核实的业务能力删除项。

## 2026-07-26～27 — 正式更名为 DAISY

- 删除：活动代码和界面不再使用 `Kit_AL` 名称；历史记录仍保留原名。

## 2026-07-27 — DAISY v1.1.1

- 删除：性能采样从正式环境检测和普通 GUI 流程移出。

- 修复：高级选项入口固定在表单最下方中央；完善日志、滚动、按钮对齐、状态配色、任务标题和快速滚动稳定性。
- 新增：GUI 环境检测显示本机工具版本，并可在用户确认后通过固定 WinGet 白名单安装缺失的 ExifTool、ffprobe 与 7-Zip。

## 2026-08-03～04 — DAISY v1.4.1

- 定位：第一个初步稳定版本。
- 改进：最终快照与 Diff 使用精确到秒的短名称，不再保留微秒和随机运行 ID；运行态 partial 继续使用内部唯一后缀，兼顾可读性与并发安全。
- 改进：以 `database_integrity`、`scan_status`、`has_file_issues`、
  `has_unstable_entries`、`has_enumeration_gaps` 五项状态取代笼统问题标记；
  源文件损坏不再被描述为数据库损坏。
- 改进：源文件问题、哈希失败、unstable 或枚举缺口保留库内证据，并在对应
  数据库同目录额外生成 `_Issues.md`；问题状态不进入数据库文件名。
- 改进：ExifTool 单文件超时按 `9 GiB` 阶梯向上取整，每阶 90 秒；策略进入快照配置，超时错误记录实际秒数和文件体积。
- 修复：元数据 profile 升至 7；曝光补偿只使用机器数值，Canon 色温采用
  `ColorTempAsShot`、白平衡优先 MakerNote，并保留照片和显式偏移视频的
  小数秒。
- 修复：从 SubIFD 恢复 DNG 有效尺寸和位深，保留其显式时区／UTC；零 GPS、
  非正数光圈／焦距和全零镜头序列号转为 `NULL` 并留下 validation 诊断。
- 修复：视频 UTC 可回退到 ffprobe `creation_time`，同时补齐 DJI 机型／编码器、
  CRM 标量作者和 AAC 音频分类；无流或无样本的小型损坏媒体会标为 error。
- 新增：`metadata_diagnostics` 保存 ExifTool Warning／Error 与字段清洗原因；
  Warning 不自动判失败，Error 同步进入 `errors`。
- 新增：快照与 Diff 使用 schema 3、`min_reader_version=1.4.1`；增量来源须
  通过指纹、SQLite、扫描、枚举、哈希和稳定性准入，单纯源文件问题不阻止
  其他有效哈希复用。
- 删除：封存文件名不再保留运行态微秒、随机 ID 或问题标记。
- 删除：移除旧 schema 读取、跨 schema Diff、旧参数别名和数据库迁移设计；
  v1.4.0 及更早数据库须重新扫描原档案。

## 2026-08-05 — DAISY v1.5.0（数据与硬盘功能域融合）

- 定位：DAISY 形成两个并列信息域。DBS 获取数据库描述的文件树、元数据、哈希与
  变化；STG 获取物理硬盘、分区、卷、Windows 存储和 smartctl 信息。两者共用
  GUI、CLI、ENV、管理员模式和测试入口，但不共享数据模型，也不自动关联文件与
  物理硬盘。
- 改进：建立 `Script/Module`，8 个可见功能模块与 8 个脚本严格一一对应：
  `ENV-01`；`DBS-11`、`DBS-12`、`DBS-21`、`DBS-31`、`DBS-32`、`DBS-41`；
  `STG-11`。GUI、CLI、脚本名、README、规格和测试使用相同编号及六字名称。
  `DBS-91 DAISY功能自检` 只位于「高级」，不占用 Module 脚本。
- 新增：唯一硬盘模块为 `STG-11 硬盘信息登记`。`storage-list` 是同一 STG-11
  脚本的内部列盘模式；`storage-collect` 按 DiskNumber 重新确认设备身份，只读
  采集详细 Windows 存储资料与完整 smartctl JSON，生成带 SHA-256 高 32 bit
  文件名指纹的 PROFILE ZIP，并可选输出外部简化 TXT。
- 新增：GUI 硬盘池展示当次扫描到的设备，并说明脱机、Windows 资料缺失或
  smartctl 未关联原因；支持逐盘勾选和「选择所有联机硬盘」。每块已选硬盘作为
  独立队列项运行并生成独立 ZIP。硬盘选择框扩大为 20 px；检测结果提示
  「若接入硬盘发生变化，请重新进行检测。」
- 删除：不再提供独立 STG 归档验证功能模块、脚本或 CLI；完整核验仍保留在底层，
  并在每个 ZIP 发布后自动执行，覆盖文件名指纹、安全路径、成员集合、Manifest、
  时间对、成员字节数和 CRC。
- 新增：STG ZIP 使用独立 `archive_schema_version=3`，默认输出到
  `Output\Storage`，执行 no-clobber 发布；访问或命令层缺口会生成明确标为
  `incomplete` 的诊断归档。
- 改进：`ENV-01` 新增 smartctl 发现、版本、只读扫描和 Windows 存储查询；
  ExifTool、ffprobe、7-Zip、smartctl 的独立安装按钮改为始终显示，并集中放入
  ENV-01 任务设置页的「软件安装」区，以等宽 2×2 布局呈现，不再占用底部辅助
  操作行；用户逐项确认后通过固定 WinGet 白名单处理，已安装状态和可用更新由
  WinGet 判断。
- 改进：顶栏固定为 `文件｜面板｜高级｜视图｜帮助`，菜单栏改用浅米黄色底色。
  「面板」包含环境、数据、硬盘三个子菜单，功能模块行标题为「环境 ENV」「数据
  DBS」「硬盘 STG」；「高级」包含「工具路径」「哈希比例」、动态「显示／隐藏
  命令预览」和「DAISY功能自检」。所有手动工具路径统一支持恢复自动发现；
  DBS-11 独立哈希抽验和 DBS-31 内容哈希抽样集中到顶部哈希比例菜单。
- 改进：任务设置不再出现页内「展开后勾选」参数。故障恢复改为「不启用／启用」
  下拉项，根标签映射直接显示为文本输入；参数默认值和 CLI 语义不变。所有设置
  下拉框在未展开时拦截鼠标滚轮，防止滚动页面时误改选项。
- 改进：STG-11 的外部简化 TXT 使用“生成／不生成”下拉选择，默认不生成；CLI
  `--summary-txt` 与归档行为保持不变。
- 新增：功能模块标题栏常驻管理员模式开关，直接显示开启／关闭状态；只在空闲且
  当前进程未提权时允许开启。用户确认后通过 Windows UAC 启动新 GUI，只有新
