# DAISY 版本演化规格（v1.0.2～v1.3.4）

- 状态：**现行版本历史摘要**。
- 当前版本：**DAISY v1.3.4**。
- 范围：从 `Kit_AL v1.0.2` 到当前 `DAISY v1.3.4`。
- 当前技术语义见[技术规格](Spec_DAISY_Technical.md)。

本文只保留影响产品定位、数据契约、兼容性和用户工作流的版本变化，不复述
开发期的全部临时目录、讨论方案或逐提交过程。

## 三、关键版本变化

### 3.1 Kit_AL v1.0.2：证据引擎成形

`v1.0.2` 已是完整的命令行系统，而不是普通文件清单脚本：

- 全程本地运行，扫描源目录保持只读；
- 每次扫描生成独立、自描述、封存后不可变的 SQLite 快照；
- 记录文件树、时间、规范化元数据、Raw Payload、File ID、SHA-256、
  压缩包成员和错误；
- 提供环境检测、完整登记、快速清点、格式校验、哈希巡检、快照 Diff
  和报告导出。

当时使用 SQLite 加 sidecar 的封装协议。sidecar 保存事件、manifest 和完整
数据库摘要，这一协议后来被 `v1.3.0` 的单 SQLite 取代。

### 3.2 Kit_AL v1.0.3：实测校准

`v1.0.3` 根据 4 组真实机械硬盘运行记录修正性能和功能描述：

- 区分 3.5 英寸 HDD 与 2.5 英寸移动 HDD；
- 删除缺少实证支持的统一速度和规模承诺；
- 明确 Quick 主要受文件数量和目录形状影响；
- 明确元数据阶段主要受适用文件数量、格式组合和外部工具影响。

这一版本主要修正文档、性能口径和权威边界，不改变扫描算法、参数、schema、
状态机或输出语义。

### 3.3 Kit_AL v1.1.0：GUI 成为薄前端

`v1.1.0` 新增 Tkinter／ttk GUI，覆盖全部业务任务，并提供路径选择、参数校验、
命令预览、后台子进程、实时日志、停止控制和结果目录访问。

GUI 不复制扫描、哈希或 Diff 逻辑，而是调用统一 CLI。这一边界延续至当前
版本。

### 3.4 正式改名为 DAISY

项目从 `Kit_AL` 正式改名为 `DAISY`，并统一修改模块名、import、启动器、
CLI 入口、测试钩子、文档和 GUI 品牌。随后确定正式全称：

```text
Database for Archive Integrity by Suzuran Ye
```

改名没有改变档案证据引擎的核心定位。

### 3.5 DAISY v1.1.1：用户检测与开发测试分离

- `env-check` 只执行工具发现、版本读取、只读冒烟和 SHA-256 验证；
- 性能采样迁入开发工具；
- GUI 环境页不再向普通用户暴露性能基准参数。

### 3.6 v1.2.0：设计过渡点

历史记录曾用 `v1.2.0` 规划工具路径继承、sidecar 调整和新产物形式，但没有
保留下来的独立正式发布检查点。因此本文不把它描述为与 `v1.1.1`、
`v1.3.0` 同等确定的发布版本。

### 3.7 DAISY v1.3.0：产物协议升级

`v1.3.0` 是主要兼容性分界：

- Full 默认读取每个文件并计算完整 SHA-256；
- Full／Quick 成功产物改为单个、自描述 SQLite；
- `snapshot_manifest` 和 `run_events` 内嵌数据库；
- 不再默认兼容旧 sidecar、松散 manifest 和旧命名；
- 数据库封存后使用完整数据库 SHA-256 的高 `32 bit` 形成
  `_XXXXXXXX.sqlite` 文件名；
- GUI 获得阶段、当前工作、速度、ETA、计数和错误等结构化进度；
- 多目录可以分别排队生成，也可以合并成一个多 root 快照；
- `.partial.sqlite` 保留独占锁和断点续传。

### 3.8 DAISY v1.3.1：可维护发布结构

- 代码整理到 `Script/Lib`、`Script/Tool` 和 `Script/Test`；
- 现行规范集中到 `Spec`；
- 删除研发期标签、旧报告和不连续设计编号；
- GUI 增加项目自检；
- 修复测试与外部工具调用中的资源释放问题；
- README 面向普通用户，技术规格面向维护者。

### 3.9 DAISY v1.3.2：公开源码基线

- Diff 在工具版本相同时排除只因读取而变化的 ExifTool
  `FileAccessDate`，减少元数据假阳性；
- 其他元数据字段变化仍正常检出；
- 测试动态生成合法微型媒体并截断，验证损坏检测；
- 删除未投入正式路径的 `block_hashes` 和
  `hash_coverage=partial`；
- 依赖安装改为逐项说明、逐项确认；
- 加入 MIT License、隐私边界和公开仓库忽略规则。

公开仓库在这一版本重新初始化，因此 `v1.3.2` 以前的开发史不能只靠当前公开
Git 对象证明。

### 3.10 DAISY v1.3.3：运行与数据能力

运行与数据能力：

- PowerShell 按「手动路径 → `PATH` → Windows 常规安装位置」发现；
- 正式兼容 Windows PowerShell 5.1 和 PowerShell 7.x；
- 坏候选不会阻断后续候选，环境检测实际执行 `Get-FileHash`；
- 新增 additive `video_gps_points`，规范化视频文件级 ISO 6709 位置；
- 元数据 profile 升至 2，`schema_version` 仍为 1。

### 3.11 DAISY v1.3.4：GUI 与 Diff 可靠性修复

- `22 check-hash` 与 `23 check-format` 必须显式指定当前档案根目录，
  不再回退到快照中的旧绝对路径；
- Diff 在同版 ExifTool Raw Payload 复核中排除 `SourceFile`、
  `Directory` 和 `FileAccessDate` 等提取环境字段，避免盘符或根目录迁移
  产生元数据假阳性；
- 内嵌元数据的真实变化仍照常检出；
- `SCANNER_VERSION` 升至 `1.3.4`，`schema_version` 仍为 1。

任务编号固定为：

| 编号 | 任务 |
|---:|---|
| 10 | 环境检测 |
| 11 | 完整登记 |
| 12 | 快速清点 |
| 21 | 快照对比 |
| 22 | 哈希校验 |
| 23 | 格式校验 |
| 31 | 导出报告 |

GUI 完善：

- 默认目标窗口为 `1920x1080`，小屏幕自动收缩；
- 日志区默认可见，表单与日志仍可拖动调整；
- 侧栏归并为准备、运行、分析和导出；
- 主标题与侧栏任务名统一；
- 滚动条移除中间图案，并避免下拉选项被滚轮误改；
- 顶部重复提示卡删除，高级选项入口移至常规字段之后；
- “就绪／运行／完成”使用清晰的矩形状态徽标；
- 左上品牌使用带正负极的极简莫比乌斯环。

## 四、兼容性边界

| 对比项 | Kit_AL v1.0.2 | DAISY v1.3.x |
|---|---|---|
| 快照封装 | SQLite＋sidecar | 单个自描述 SQLite |
| 外部数据库摘要 | sidecar 完整 SHA-256 | 文件名高 `32 bit` 指纹 |
| 运行事件与 manifest | sidecar／松散文件 | 内嵌 SQLite |
| 默认 Full 哈希 | 依配置 | 完整 SHA-256 |
| GUI | 无 | Tkinter／ttk 薄前端 |
| 跨版本直接 Diff | 默认不保证 | 受产物准入、指纹和 profile 约束 |

`schema_version=1` 只表示核心表结构仍在同一版本号下演化，不代表
`Kit_AL v1.0.2` 与 `DAISY v1.3.x` 的封装、准入和证据链可以直接互换。

## 五、持续不变的原则

从 `Kit_AL v1.0.2` 到 `DAISY v1.3.4`，以下原则保持稳定：

- 源档案只读；
- 本地运行，不依赖网络服务；
- 每次扫描生成独立证据快照；
- 完整哈希使用 SHA-256；
- 格式校验、哈希校验、Diff 和报告导出不回写既有快照；
- GUI 与 CLI 共用同一业务实现。

## 六、证据边界

- `v1.0.2` 以前的逐项开发过程没有足够资料完整恢复；
- `v1.2.0` 只能确认是设计过渡点，不能确认独立正式发布；
- 公开仓库在 `v1.3.2` 重新初始化，旧提交关系已不在当前公开 Git 中；
- `v1.0.2～v1.3.2` 的阶段级事实来自历史审计、测试结果和当时记录；
- `v1.3.3` 以本地源码、技术规格和 Git 检查点为准；
- `v1.3.4` 以当前本地源码、技术规格、实测矩阵和回归测试为准。
