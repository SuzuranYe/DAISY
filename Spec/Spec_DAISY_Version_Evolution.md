## 2026-08-11 — DAISY v1.6.8（界面与核验优化开发版）

- 核验：新增默认完全不选的「已有数据库／无数据库」首级选择；未选择时隐藏下方全部内容。
  已有数据库后只先展开「路径未变／路径变化」，第二层完成后才显示其余设置。原盘符和路径
  未变时直接采用快照记录的根路径，只有变化时才显示根目录映射池；无数据库
  时可直接遍历一个或多个目录并执行格式、容器和 RAW 检查，不伪造哈希一致结论。
- 核验：补充独立「哈希复核」按钮，数据库模式可重新计算全部有效 SHA-256 基准；直接模式
  因没有基准而禁用。统一 `verify` CLI 增加互斥 `--direct` 输入，并允许数据库原路径未变时
  省略 `--root`。核验项目默认选择除 rawpy/LibRaw 外的全部项目；一份合并快照可对应最多
  9 个根目录，因此数据库输入仍只允许一份，但根目录池保留最多 9 项。
- 界面：顶部 6 个功能入口改用与设置标题一致的六字完整名称；顶部入口与右下角任务按钮
  使用同一套较大的无描边常驻控件规格。删除重复的「功能模块」标题，最左入口到左、上、
  下三边的距离与相邻按钮间距一致；顶部右侧删除「展开模块／收起模块」及「视图→功能栏」
  开关，只保留「重置软件」。三色细带移动到功能栏和下方内容之间。扫描续传提示移到设置标题
  下方的独立卡片。
- 配色：以《明日方舟_孤星_配色取样_修复版_v2.pptx》为权威来源，修正先驱青绿和工程黄
  的近似取样，并统一档案黑、信号橙、浅黄字、档案深红及四个辅助色；停止动作使用信号橙，
  工程黄只承担警告和续传提示。补充使用暖白、板岩、科研蓝、鼠尾草和天青等用户
  提供色板：暖白取代大面积浅黄绿色，功能模块使用灰褐，设置区分割线上方统一使用鼠尾草，
  板岩标题栏和统一科研蓝进度恢复进度／日志层级；开始／暂停／产出／就绪使用科研蓝／天青／卡其／
  板岩。代码中的语义色全部指向规格登记的核心或可选色值，不再保留表外旧色。
  档案数据解析生成的 HTML 报告样式同步收敛到同一批准色板，并由源码白名单测试防止回退。
- 控件：宽度为 12 字符的浏览、选择、展开／收起与日志工具按钮统一增高；元数据三态统一
  字体与字重。普通有效选中态统一为鼠尾草，关闭／不采集／不输出统一为灰褐，未选候选项
  使用暖白；保存目录、普通单行输入框和内容池统一为 `1 px` 灰褐边界。
- 界面：扫描、核验和数据解析的输入添加、解析数据库与检测硬盘使用科研蓝高对比样式，数据库
  选择使用天青输入样式；所有页内工作流按钮严格采用完整扫描的标准尺寸，以配色而非额外放大
  表达重要程度。快照对比的快照输入恢复中性「浏览」。目录、根目录映射、配对和硬盘
  内容使用池式容器，操作按钮位于池外、内容列在下方池内；数据解析的纯操作说明行取消多余
  包围线。硬盘池移除「全选／取消选择」，检测按钮独立位于池上方；管理员未启用时使用浅黄
  区域和暗橙主按钮，启用后切换为青绿色状态区。
- 进度：队列、任务阶段和本阶段三行均保留右侧读数位置；可计算时显示整数百分比，暂不可
  计算时显示「计算中」。三条进度统一使用科研蓝，进度槽统一为石灰；三行标题、
  说明和百分比在普通状态统一使用板岩，结束时再整体切换为成功、警告或错误色。
- 界面：数据解析未选择数据库时只显示「选择」，选择后只增加「解析数据库」；识别成功后
  一次显示导出范围、数据模块、四种格式和目录，默认选择「全量」、全部可选择模块及全部格式；
  自定义必须至少选择一个模块。数据库选择按钮独占第一行，完整路径置于第二行；失败或任一
  必需选择未完成时，「开始」使用灰色禁用态。数据模块改用固定按钮列与独立间距列，修正各行
  未完全对齐。
- 界面：快照对比默认完整显示基础设置并选择「单目录」；只有选择「多目录」才展开两行式根
  目录名配对；更换快照会恢复单目录并清除旧配对。扫描建库默认完整显示，选择完整扫描、全新
  生成、分别生成及全部采集内容。硬盘登记先检测、再显示硬盘选择，选中至少一块硬盘后才显示
  输出设置；各
  设置、进度与日志的展开／收起按钮保持固定 x 轴位置，点击后不再残留虚线焦点框；顶部功能栏
  只保留「重置软件」，并与设置、进度、日志操作组对齐到同一右边界，后三者统一使用四边等距
  外边距；设置区「恢复默认」改名为「恢复设置」。
- 环境：检测清单增加当前 Python 版本，并提供固定 Python 3.14 WinGet 包的安装或更新入口；
  7 个环境状态／安装项与扫描模式按钮同宽、高度约为其 1.5 倍，检测成功的第二行直接显示
  版本号，不再显示笼统的「可用」。修复 GUI 缓存层误删 Python 探测结果；PowerShell 状态
  只显示主次版本。缺失工具或 rawpy 时仍归类为「环境检测完成」并明确列出缺失项。增加默认
  关闭的「检测报告」，开启后才显示目录并实际导出 JSON，缺失场景也可导出清单。
- 窗口：新安装、非法配置回退和重置后的默认窗口目标改为 `1920×1080`，仍约束在当前显示器
  工作区内；用户已经保存的合法窗口大小继续保留。
- 面板：设置、进度和日志正文默认收起；运行时收起设置并展开进度和日志。所有任务结束 2 秒
  后只收起进度，日志保持展开并接管进度正文释放的高度，不自动展开设置；倒计时内手动切换
  进度时以用户操作为准。
- 面板：分阶段页面的章节标题由固定页面结构决定，不再因当前已展开字段数变化而动态插入；
  六个功能页均在首批内容前显示非重复章节标题，补齐扫描设置、解析输入和硬盘登记准备，
  档案数据核验在选择核验方式前后保持首项位置稳定。
- 文案：按真实执行边界复核 GUI、CLI、README 和现行规格。六个功能说明明确封存快照、
  只读解析、无数据库核验及 Python 检测；硬盘检测改为准确描述清单读取与 SMART 目标匹配；
  数据库来源统一显示「数据库生成程序版本」，解析范围统一为「全量／摘要／自定义」，模块
  可用状态统一为「可选择」。环境页「软件安装」改为「安装与更新」，PowerShell 明确为
  手动管理，不再笼统标成系统提供。
- 测试安全：删除会反复创建完整窗口的 71 项真实 Tk／桌面测试代码及其专用辅助函数；默认
  回归和 GUI 功能自检只保留不创建桌面窗口的参数、状态与编排测试，视觉验收改为 AI 按需
  手动打开软件执行。
- 版本：`SCANNER_VERSION` 与 `APP_VERSION` 更新为 `1.6.8`；快照 schema 3、统一扫描
  schema 4、硬盘归档 schema 3、元数据 profile 7 和既有恢复契约均不变。

## 2026-08-11 — DAISY v1.6.7（致命错误修复版）

- 定位：修复会阻断 GUI 完整扫描哈希计算、导致进程异常退出，以及默认功能自检可能造成
  桌面严重卡顿或卡死的致命问题；建议所有仍在使用下表受影响版本的用户立即升级。
- 哈希修复：Windows 控制管道不再由后台线程阻塞读取缓冲 `stdin`，改为轮询匿名管道后
  读取原始字节；哈希工作进程现在可以完成 `spawn → ready → publish`，停止控制也能及时退出。
- 自检修复：真实 Tk／桌面集成测试改为显式选择加入，默认功能自检只运行不创建完整窗口的
  安全测试，避免一次自检反复创建大量 GUI 实例。
- 回归保护：新增「控制管道保持打开时仍能启动并完成哈希工作进程」的跨进程测试，以及
  Windows 真实匿名管道的停止与命令路由测试。
- 兼容：`SCANNER_VERSION` 与 `APP_VERSION` 更新为 `1.6.7`；快照 schema 3、统一扫描
  schema 4、硬盘归档 schema 3、元数据 profile 7 和既有恢复契约均不变。

### 已确认的失效版本与边界

| 正式版本 | 已确认状态 | 精确边界 |
|---|---|---|
| v1.5.1 | 默认功能自检存在桌面卡顿或卡死风险 | 自检会运行包含真实 Tk 窗口的单元测试；扫描哈希控制管道故障尚未引入 |
| v1.6.0、v1.6.2、v1.6.3、v1.6.4、v1.6.5、v1.6.6 | GUI 完整扫描的 SHA-256 采集功能实际失效；默认功能自检存在桌面卡顿或卡死风险 | GUI 始终保持控制管道打开，Windows `spawn` 哈希工作进程无法进入就绪状态；无控制管道的直接 CLI 哈希路径不属于该失效范围 |

Git 定位证据：真实 Tk 单元测试由 `0c33f85` 引入，首个包含它的正式标签为 `v1.5.1`；
整组 GUI 扫描窗口测试由 `569aebc` 引入。隔离哈希工作进程先由 `25608be` 引入，随后
`8536d91` 加入阻塞式控制管道读取并形成完整故障链；后三项的首个正式标签均为 `v1.6.0`。

`v1.6.1` 只有阶段性代码、没有正式 Git 标签，因此不列为正式失效版本；该阶段代码确实继承了
上述两个缺陷。这里的「桌面卡顿或卡死风险」是已复现的高风险测试路径，不等同于断言每台电脑
都会发生整机硬锁死；GUI 哈希工作进程无法就绪及退出时的 Python 致命错误则已被确定性复现。

## 2026-08-10 — DAISY v1.6.4（长期稳定版本）

- 定位：继 v1.4.1 后第二个明确适合长期部署、并作为后续兼容维护基线的生产版本。
- 基线：继承 v1.6.3 的 UI、扫描、Diff、核验、解析、硬盘登记和环境检测能力；不升级
  快照或硬盘归档的数据结构，不改变扫描、建库、Diff 或报告数据协议。
- 修复：档案数据核验在当前会话尚未完成运行环境检测时显示「需要先运行环境检测」；
  ExifTool、ffprobe、7-Zip 和 rawpy/LibRaw 灰显，开始操作被预检拒绝，避免把默认选择
  误解为工具已通过检测。
- 交互：环境检测完成后，只启用本次清单确认可用的外部项目；不可用项目保持灰色并显示
  原因。暂时灰显不会覆盖用户保存的开关选择，能力恢复后按原选择恢复。
- 视觉：待检测信息改用与硬盘登记管理员状态相同层级的琥珀色提示卡；硬盘选择区的
  「全选／取消选择」改为与「浏览」相同的小按钮尺寸和样式。
- 对齐：硬盘登记的「管理员模式」改为与「收起设置／展开进度」相同尺寸，并与左侧权限
  状态标题在同一 Y 轴居中。
- 重置：「重置软件」会同时清除本次环境清单状态，核验页重新回到待检测状态。
- 文案：底部「打开结果目录」按钮缩短为「产出」；命令、目录解析、悬停说明和完成后
  两次绿色提示保持不变。
- 设置：窗口大小预设按 `1366×768`、`1600×900`、`1920×1080` 升序排列；
  「结果目录提示」改名为「结果目录弹窗」，默认值、配置键与结束行为不变。
- 版本：`SCANNER_VERSION` 与 `APP_VERSION` 更新为 `1.6.4`；快照 schema 3、
  统一扫描 schema 4、硬盘归档 schema 3、元数据 profile 7 和既有恢复契约均不变。

## 2026-08-07 — DAISY v1.6.0（可靠性、兼容与报告重构）

- 改进：GUI 数据域收敛为「扫描、对比、核验、数据库解析」。旧 `full-scan／quick-scan／
  check-hash／check-format／export-report` 参数和投影继续作为兼容入口保留。
- 新增：统一 `scan` 使用 schema 4、独立续传契约、run session、entry attempt、CAS 状态、
  lease／心跳和 no-clobber 发布。支持同会话暂停／继续、保存进度并退出、下次确认续传，
  以及与之语义不同的停止任务。
- 改进：v1.5.1 完整扫描的 schema 3 续传以 ScanLock、严格版本匹配、重新枚举和文件状态
  复用为主；schema 4 进一步明确记录 session、attempt、checkpoint、lease 和恢复提示。
  暂停只在当前进程内继续；保存并退出后仅在下次启动显示提示，用户仍须准备续传并点击
  开始。已提交文件保留，当前文件可能从起点重试。
- 新增：哈希读取使用隔离 worker。无进展 timeout 默认 90 秒，每 9 GiB 增加 90 秒；提供
  继续等待、跳过并记录、停止并保留续传，无人选择时默认继续等待。数值进度最多 500 ms、
  可选当前文件最多 100 ms 发送一次。
- 新增：Full 可附加默认关闭的格式校验。RAW 深度校验默认关闭且从属于格式校验，通过
  统一能力层检查 rawpy，并在独立子进程实际执行 LibRaw 解码；不支持类型只统计，解码
  失败、截断和 timeout 进入伴随报告，不改变 SQLite schema。
- 新增：统一 `verify` 组合 stat、内容哈希、格式与 RAW 深检。哈希和格式结论、抽样和报告
  保持独立；unsupported 不作为文件问题。
- 新增：数据解析功能重构为数据库解析。Reader 自动识别快照／Diff 和模块能力，提供三种内容
  预设、快照 15 个模块、Diff 6 个模块，以及自包含 HTML、中文 XLSX、CSV、JSONL 和
  manifest；输入只读、流式投影、staging 和 no-clobber 发布。
- 新增：统一 Reader 只读支持 schema 3／4。快照对比的跨版本 Diff 覆盖 3→3、3→4、4→3、
  4→4；旧库缺少新能力时显示 `NULL／不可用`，不迁移、不回写、不伪造 0。
