# DAISY 更新日志（v1.0.2～v1.4.1）

- 当前版本：**DAISY v1.4.1**。
- 更新日期：**2026-08-04**。
- 日期来自现存历史记录和 Git 检查点；`v1.2.0` 只能确认是设计过渡点，不能写成已确认的正式发布。
- 当前数据和运行语义见[技术规格](Spec_DAISY_Technical.md)。

## 2026-07-18 — Kit_AL v1.0.2

- 新增：形成纯本地、源目录只读的档案证据工具；提供 Full、Quick、哈希校验、格式校验、Diff 和报告导出。
- 新增：以 SQLite 保存文件树、时间、规范化元数据、Raw Payload、File ID、SHA-256、压缩包成员和错误记录。
- 改进：补齐统一入口、Diff 自动 root 配对、逻辑路径和进度节流；现存记录可证明当日已用于 TB 级真实目录。
- 删除：没有发现可核实且属于本版本的删除项。

## 2026-07-21～22 — Kit_AL v1.0.3

- 改进：根据 4 组真实机械硬盘运行记录区分 3.5 英寸 HDD 与 2.5 英寸移动 HDD 的表现。
- 修复：把 Quick、元数据和哈希阶段的性能描述改成受文件数量、目录形状、格式组合与介质影响的实测口径。
- 删除：移除缺少证据的统一速度和规模承诺；schema、算法和产物语义不变。

## 2026-07-26 — Kit_AL v1.1.0

- 新增：加入不依赖第三方 Python 包的 Tkinter／ttk GUI，覆盖全部业务任务。
- 新增：提供路径选择、参数校验、命令预览、后台子进程、实时日志、停止控制和结果目录入口。
- 改进：GUI 保持为统一 CLI 的薄前端，不复制扫描、哈希或 Diff 逻辑。
- 删除：没有发现可核实的业务能力删除项。

## 2026-07-26～27 — 正式更名为 DAISY

- 改进：项目、模块、入口、import、测试、文档和 GUI 品牌由 `Kit_AL` 统一改为 `DAISY`。
- 新增：确定全称 `Database for Archive Integrity by Suzuran Ye`。
- 删除：活动代码和界面不再使用 `Kit_AL` 名称；历史记录仍保留原名。

## 2026-07-27 — DAISY v1.1.1

- 改进：`env-check` 只保留工具发现、版本读取、只读冒烟和 SHA-256 验证。
- 修复：把面向用户的环境可用性检测与开发性能测试分开，避免把基准结果误当环境结论。
- 删除：性能采样从正式环境检测和普通 GUI 流程移出。

## 2026-07-27 前后 — v1.2.0 设计过渡点

- 设计：记录工具路径继承、sidecar 调整和新产物形式的过渡方案。
- 边界：现有证据不足以确认它曾形成独立正式发布，因此不把设计日期冒充发布日期。
- 删除：不适用；该条只记录可证实的设计阶段。

## 2026-07-27～28 — DAISY v1.3.0

- 新增：Full 默认对每个可读文件计算完整 SHA-256。
- 新增：Full／Quick 成功产物改为单个自描述 SQLite，并内嵌 `snapshot_manifest`、`run_events` 和结构化进度。
- 新增：数据库文件名使用完整数据库 SHA-256 的前 8 个十六进制字符作为快速指纹；支持多 root 排队／合并、独占锁和 partial 续传。
- 删除：默认产物不再使用旧 sidecar、松散 manifest 和旧命名协议；这是明确的兼容性分界。

## 2026-07-29 — DAISY v1.3.1

- 新增：发布结构整理为 `Script/Lib`、`Script/Tool`、`Script/Test` 和 `Spec`。
- 新增：GUI 环境页加入项目自检入口，README 与技术规格分别面向普通用户和维护者。
- 修复：测试和外部工具调用的资源释放问题。
- 删除：移除研发期标签、旧报告和不连续的设计编号。

## 2026-07-29 形成、2026-07-30 公开 — DAISY v1.3.2

- 定位：第一个公开发行版。
- 修复：Diff 在同版 ExifTool 比较中排除只因读取而变化的 `FileAccessDate`，其他真实元数据变化仍可检出。
- 新增：测试运行时生成合法微型媒体并截断，验证损坏文件检出；加入 MIT License、隐私边界和公开仓库忽略规则。
- 改进：依赖安装流程改为逐项说明、逐项确认。
- 删除：移除未接入正式路径的 `block_hashes` 表和 `hash_coverage=partial` 值。

## 2026-07-30 — DAISY v1.3.3

- 新增：PowerShell 支持 Windows PowerShell 5.1 和 PowerShell 7.x，发现顺序为手动路径、`PATH`、Windows 常规安装位置。
- 修复：坏候选不再阻断后续候选；环境检测实际运行 `Get-FileHash`，减少“已安装但 PATH 未刷新”的误判。
- 新增：加入 `video_gps_points`、ISO 6709 视频文件级位置规范化和 `GPS_inventory_video.csv`；元数据 profile 升至 2。
- 删除：没有数据库核心表删除，`schema_version` 仍为 1。

## 2026-07-30 — DAISY v1.3.4

- 修复：日志区默认可见，滚动条滑块比例在顶部和底部保持一致，滚轮不再误改下拉选项，底部按钮与状态徽标对齐。
- 改进：默认窗口目标为 `1920x1080` 并适配较小屏幕；主标题与侧栏统一，任务固定为 10、11、12、21、22、23、31。
- 改进：21 为“分析”、22 为“哈希校验”、23 为“格式校验”、31 为“导出报告”；21／22 使用用户指定的当前 root，适应盘符或根目录变化。
- 新增：页面和系统窗口统一使用带正负极的平滑单色莫比乌斯图标；独立哈希抽验比例移入高级设置并解释用途。
- 修复：Diff 排除 `SourceFile`、`Directory`、`FileAccessDate` 等提取环境字段，避免 root 迁移造成元数据假阳性。
- 删除：移除静置窗口可调项、顶部重复提示和滚动条中间图案。

## 2026-07-31 — DAISY v1.4.0

- 新增：完整扫描明确分为“基础元数据”和“全量元数据”；前者保存规范化字段但不写 `raw_payloads`，后者额外保留原始后端证据。
- 新增：全量元数据为本地所有文件尝试保存 ExifTool 原始 JSON，并只为视频、音频和 GIF 保存 ffprobe 原始 JSON；视频和音频在基础模式仍运行 ffprobe 以生成规范化容器与流字段。
- 新增：`.jfif` 归入 `photo_jpeg`、`.doc` 归入 `document`、GIF 使用 `image_gif` 并进入通用照片规范化表；元数据 profile 升至 6。
- 新增：格式校验为 GIF 加入 ExifTool＋ffprobe 双检，为旧 DOC 加入 OLE 魔数和 `7z t` 结构测试。
- 新增：新快照与 Diff 使用 `schema_version=2` 和 `min_reader_version=1.4.0`；v1.4 reader 可只读接纳 schema 1／2，并记录跨 schema Diff 的两侧版本。
- 修复：高级选项入口固定在表单最下方中央；完善日志、滚动、按钮对齐、状态配色、任务标题和快速滚动稳定性。
- 新增：GUI 环境检测显示本机工具版本，并可在用户确认后通过固定 WinGet 白名单安装缺失的 ExifTool、ffprobe 与 7-Zip。
- 新增：`Script/Script_DAISY_Install_Python.ps1` 只负责无 Python 环境的 Python 3.14 引导安装。
- 新增：GUI“清理缓存”逐项记录并清除项目内可重建的 Python／测试缓存和当前窗口工具路径缓存，不触碰 `Output` 或正式产物。
- 修复：基础／全量快照的规范化表保持一致，Diff、哈希、格式和导出工具明确校验 schema／文件名指纹／当前 root。
- 删除：移除根目录的全依赖安装脚本；外部工具安装统一进入 Python 可用后的 GUI 环境页。
- 删除：不再把“是否保留 Raw Payload”描述成“是否采集 EXIF”；旧 `--no-raw-payload` 仅作为隐藏兼容别名保留。
- 删除：不再为静态照片、文档、压缩包和普通文件保存价值有限的 ffprobe 原文。
- 兼容：`v1.3.x`、Kit_AL 及更早 reader 不保证正确读取 v1.4 产物；这项“不前向兼容”不否定 v1.4 对既有封存快照的向后只读能力。

## 2026-08-03～04 — DAISY v1.4.1

- 定位：第一个初步稳定版本。
- 改进：最终快照与 Diff 使用精确到秒的短名称，不再保留微秒和随机运行 ID；运行态 partial 继续使用内部唯一后缀，兼顾可读性与并发安全。
- 改进：以 `database_integrity`、`scan_status`、`has_file_issues`、
  `has_unstable_entries`、`has_enumeration_gaps` 五项状态取代笼统问题标记；
  源文件损坏不再被描述为数据库损坏。
- 改进：源文件问题、哈希失败、unstable 或枚举缺口保留库内证据，并在对应
  数据库同目录额外生成 `_Issues.md`；问题状态不进入数据库文件名。
- 改进：ExifTool 单文件超时按 `9 GiB` 阶梯向上取整，每阶 90 秒；策略进入快照配置，超时错误记录实际秒数和文件体积。
- 修复：元数据 profile 升至 7；曝光补偿只使用机器数值，Canon 色温采用
  `ColorTempAsShot`、白平衡优先 MakerNote，并保留照片和显式偏移视频的
  小数秒。
- 修复：从 SubIFD 恢复 DNG 有效尺寸和位深，保留其显式时区／UTC；零 GPS、
  非正数光圈／焦距和全零镜头序列号转为 `NULL` 并留下 validation 诊断。
- 修复：视频 UTC 可回退到 ffprobe `creation_time`，同时补齐 DJI 机型／编码器、
  CRM 标量作者和 AAC 音频分类；无流或无样本的小型损坏媒体会标为 error。
- 新增：`metadata_diagnostics` 保存 ExifTool Warning／Error 与字段清洗原因；
  Warning 不自动判失败，Error 同步进入 `errors`。
- 新增：快照与 Diff 使用 schema 3、`min_reader_version=1.4.1`；增量来源须
  通过指纹、SQLite、扫描、枚举、哈希和稳定性准入，单纯源文件问题不阻止
  其他有效哈希复用。
- 删除：封存文件名不再保留运行态微秒、随机 ID 或问题标记。
- 删除：移除旧 schema 读取、跨 schema Diff、旧参数别名和数据库迁移设计；
  v1.4.0 及更早数据库须重新扫描原档案。
